主入口是任务分类

划分为5类任务

1. 代码问题，必须调用智能体闭环开发进行工作
   
   1. 如果涉及到修改bug，则最重要的问题是如何找到bug，这里需要一个找bug的skill
   
   2. 写代码可能涉及大量内容，所以需要并行调用子智能体加速
   
   3. 写完之后必须真实验证
   
   4. 部分任务需要github协同，因此需要有github相关技能
   
   5. 一个任务文件夹是需要维护的，因此需要有一个新建任务的skill和长期维护的skill
2. 文稿撰写，必须调用文稿撰写的skill，包括去AI味的skill
3. 深度调研，必须调用相关skill
4. 专项任务，这里需要读取myworkflow外的skill，看有没有对应的专项任务skill，并进入子图。
   1. 这里是否可以通过skill内部的配置文件存当前有哪些别的专项skill，在工作的时候直接读取内部json文件来判断是否有对应的专项任务（js分两层，一层为有哪些任务，第二层为该任务下有什么skill）
   2. 需要一个skill专门维护专项任务的配置文件
   3. 我自己做的插件、技能都需要自动配置在专项skill内或者单独留一个文件用来辅助(2)的配置文件更新
5. 简单任务，比如回答小问题等，直接回答



在这之外，有并行的skill体系，这些并行的skill不参与任务分类，但是在不同分类的任务进行过程中都可能涉及调用的

1. 关于子智能体，在大量任务包括但不限于代码、文稿、调研或我制作的别的专项任务skill内需要调用子智能体，则需要配套skill
   
   1. 子智能体并行加速的核心是搞清楚应该做什么、边界、接口，这样才能在没有沟通的情况下进行协作，因此发布任务的时候需要专门的skill指导
   
   2. 子智能体如何规范协作需要skill指导（这里是否可以换成hook效果更好？）
   
   3. 子智能体返回之后需要检查子智能体的成果

2. 关于AI谄媚的问题，需要单独一个小skill分析，来减少AI过度信任

3. 任何任务开始之前，都需要足够详细理解用户需求，这里需要skill

4. 关于AI如何思考问题，如何与人类协助，这里单独需要一个skill辅助，我命名为lessismore，这个skill的编写是一项单独的任务
