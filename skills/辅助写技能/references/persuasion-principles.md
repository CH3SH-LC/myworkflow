# Skill 设计中的说服原则

基于 Cialdini (2021) 和 Meincke et al. (2025) N=28,000 AI 对话研究。

## 七条原则

### 1. 权威性（Authority）
- **是什么**：使用命令式语言"你必须""禁止"
- **为何有效**：LLM 对高确定性指令的遵循度远高于建议。"你应该考虑 X"≈30%；"你必须做 X"≈90%
- **何时用**：核心规则、不可跳过的步骤、硬门禁
- **注意**：不要滥用——每句都是"必须"会让关键规则淹没在噪声中

### 2. 承诺（Commitment）
- **是什么**：要求 agent 公开声明将做什么，创造一致性压力
- **何时用**：输出确认、自检 checklist、接口声明

### 3. 稀缺性（Scarcity）
- **是什么**：设置硬上限（"最多 3 轮""只有一次机会"）
- **为何有效**：无限尝试 → agent 会"先试一个再说"；上限 → "这次必须认真做"

### 4. 社会证明（Social Proof）
- **是什么**：展示"普遍做法"或"他人犯过的错误"来强化指导
- **何时用**：危险信号、常见错误、反模式

### 5. 统一性（Unity）
- **是什么**：使用"我们"的协作语言，在严格规则之间插入协作表述

### 6. 互惠性（Reciprocity）
- **是什么**：先给予（模板、参考文件、速查表），再要求（严格遵循规则）
- **注意**：谨慎使用——过度使用变成操纵

### 7. 喜好（Liking）
- **是什么**：让 skill 因为质量被喜欢——结构清晰、模板实用
- **注意**：绝对不用谄媚技巧——谄媚降低可信度

## 按 Skill 类型的组合建议

| Skill 类型 | 主导原则 | 辅助原则 | 小心 |
|-----------|---------|---------|------|
| 规则型 | 权威+承诺 | 社会证明 | 不要只用权威 |
| 技术方法型 | 权威+社会证明 | 稀缺 | 过度稀缺="随便做" |
| 模式思维型 | 统一+互惠 | 权威 | 太强权威压制创造性 |
| 参考知识型 | 互惠+喜好 | 权威 | 太弱权威不被认真对待 |

## 核心洞见

- **亮线规则**：模糊规则被绕过概率是明确规则的 5-10 倍
- **实施意图**："当 X 发生时，做 Y"比"做 Y"的遵循度高 2-3 倍
- **LLM 非人**：LLM 不会被"冒犯"——可以比对人更直接、更强调"必须"

## 道德边界
- ✅ 强化用户真实偏好的技术机制
- ✅ 让 agent 更忠实执行用户意图
- ❌ 操纵 agent 违反用户利益
- ❌ 用说服原则绕过用户明确指令
