# 文体松紧规则与正反范例

每个文体给两组内容：**松紧规则细则**（哪里可以放开、哪里必须收紧）与**一正一反两段范例**。

反例是"AI 会这么写"的典型形态，正例是同一件事说清楚之后的形态。两者的信息量应当接近——差别在于**正例把话说到了具体的对象、数字或例子上，并且没有靠四字格和升华把空隙填满**。

配套阅读：`polish-prose/references/before-after-zh.md`（分类正反例库）。

---

## 1. 说理评论

**松紧规则**

| 维度 | 规则 |
|------|------|
| 结论位置 | **首段给出**（结论检适用）。可以是判断句，也可以是"我认为 X，理由如下" |
| 句长 | 短句为主，长短交错；说理靠短句推进，长句留给限定条件 |
| 第一人称 | **可用「我」，且应当有立场**——说理评论没有立场就是综述 |
| 段落 | 3–5 句；一段一个分论点 |
| 可以松的地方 | 口语词、反问、直接的判断句（「这不对」「这笔账算不过来」） |
| 必须紧的地方 | ① 观点必须能被反驳（不可反驳的观点没有信息量）② 反方必须被真实呈现，不能立稻草人 ③ 不许用"辩证地看""既要…又要…"收场 |

**反例**

> 关于远程办公的讨论，需要从多个维度进行辩证的分析。一方面，远程办公能够提升员工的灵活性与满意度；另一方面，它也可能带来沟通效率下降等问题。因此，我们应当在两者之间寻找平衡，因地制宜、因时制宜地推进。总而言之，远程办公既是机遇也是挑战，关键在于如何科学地管理。

**正例**

> 远程办公能不能做，取决于一件事：你的交付物能不能被单独验收。写代码、做设计、做账，可以——产出摆在那里，谁写的、在哪写的都不影响判卷。做客服、带新人、谈客户，不行——这些活的产出本身就是"在场"。所以我反对的是"一刀切放开"，不是远程办公本身。我们团队试了四个月，写得最清楚的一条经验是：凡是需要两个人同时在场才能推进的事，排到每周二和周四的线下。

**差在哪**：反例是一篇"关于远程办公的综述"，删掉任何一句都不影响剩余部分；正例给了一个可证伪的判据（交付物能否单独验收），并附上了自家的试验条件。

## 2. 说明技术

**松紧规则**

| 维度 | 规则 |
|------|------|
| 结论位置 | **首段给出**（结论检适用）：本方案解决什么问题、结论是什么 |
| 句长 | 中长句为主，术语精确；但一个句子只承担一个逻辑关系 |
| 第一人称 | 少用；用「本方案」「本系统」「我们」指代实施方 |
| 段落 | 4–6 句；一段一个模块或一个决策点 |
| 可以松的地方 | 术语、代码片段、表格、精确的数字与单位 |
| 必须紧的地方 | ① 每个技术选型必须写"为什么不选另一个"② 前置定语 >12 字必拆 ③ 不许用"高性能""良好的扩展性"这类无指标的形容 ④ 数字必须带口径（P99 还是均值、哪个环境测的） |

**反例**

> 为了应对不断增长的业务需求，本方案采用微服务架构对系统进行了全面的重构。新的架构具备良好的可扩展性和高可用性，能够有效地支撑未来的业务发展。在数据存储方面，我们选用了合适的数据库方案，以满足不同场景下的数据访问需求。整体而言，本次重构将显著提升系统的整体性能与稳定性。

**正例**

> 本方案把单体拆成 6 个服务，目标只有一个：大促当天只扩订单和支付，其余不动。选 Spring Cloud 而不是 Service Mesh，是因为我们只有 2 个运维，Istio 的控制面没人兜得住。数据层保持单库，只把订单表按月分表——分库的分片键没想清楚，现在拆等于把问题推迟六个月。压测结果：拆完 P99 从 800ms 降到 310ms，测试环境 4 核 8G，脚本在 `bench/order.js`。

**差在哪**：反例的每一个形容词都无法证伪；正例的每个决策都附了"另一条路为什么不走"，数字附了口径和复现路径。

## 3. 报告公文

**松紧规则**

| 维度 | 规则 |
|------|------|
| 结论位置 | **首段给出**（结论检适用）。公文的首段就是"事项 + 结论" |
| 句长 | 平稳；避免超长句，也避免过于跳跃的短句堆叠 |
| 第一人称 | 不用。主体写具体部门或岗位（「运维组」「财务部」） |
| 段落 | 3–5 句；一段一个事项 |
| 可以松的地方 | 固定的文书格式、编号、条款化表述 |
| 必须紧的地方 | ① 任何要求必须带**责任主体 + 期限 + 可验证的交付物** ② 禁止"高度重视""加大力度""落实到位"这类不产生动作的动词 ③ 禁止在通知、纪要里做展望 |

**反例**

> 针对近期检查中发现的相关问题，各部门要高度重视，进一步提高思想认识，切实增强责任意识。要举一反三，深入排查同类问题，确保各项整改措施落实到位。同时，要进一步加强日常管理，建立健全长效机制，为下一阶段工作奠定坚实基础。

**正例**

> 本次检查发现消防通道堆物 6 处（3 楼东侧、4 楼西侧各 3 处）。请 3 楼、4 楼的楼层负责人在 9 月 20 日前清空，清空后拍照发至安全管理群。逾期未处理的，由物业统一清理，费用由所在部门承担。9 月 25 日复查。

**差在哪**：反例读完之后没有任何人知道该做什么；正例给出了地点、责任人、期限、交付物、后果和复查时间。

## 4. 叙事随笔

**松紧规则**

| 维度 | 规则 |
|------|------|
| 结论位置 | **不要求首段给结论**——这是唯一豁免结论检的一类。意义可以到最后才浮现，也可以始终不点破 |
| 句长 | 长短悬殊，允许长句；节奏由情绪和场景决定，不由逻辑决定 |
| 第一人称 | **必需**。第三人称的随笔几乎必然写成说明文 |
| 段落 | 2–8 句，随事走；一段可以只有一句话 |
| 可以松的地方 | 细节、感官描写、跑题、半成型的想法、不解释的留白 |
| 必须紧的地方 | ① 细节必须是**具体的、可指认的**，不是"令人难忘的"这类评价 ② 禁止在段尾升华（节奏检）、禁止结尾喊口号（首尾检） ③ 情绪必须由事实承载，不能直接宣布 |

**反例**

> 那是一个令人难忘的下午。阳光透过窗户洒进房间，一切都显得那么宁静而美好。我不禁陷入了深深的回忆之中，思绪万千，感慨万分。时光荏苒，岁月如梭，许多往事都已随风而逝，但有些记忆却永远留在心底，历久弥新。

**正例**

> 下午三点，房间里只有打印机在响。我在改一份已经改到第七版的方案，改到"项目背景"那一段时，忽然发现第一版里我写的是"这个项目可能做不成"。后来这段被删了，因为评审时领导说背景部分要写积极一点。我盯着屏幕坐了大概十分钟，然后接着往下改。

**差在哪**：反例里的"宁静""美好""思绪万千"是情绪标签，读者接不到任何画面；正例没有说"我很难过"，只写了一个具体动作和一句被删掉的话。

## 5. 口播演讲

**松紧规则**

| 维度 | 规则 |
|------|------|
| 结论位置 | **开头 15 秒内**给出（结论检适用）。听众的注意力窗口在这里 |
| 句长 | 短句为主，**每句是一个换气单位**；避免从句套从句 |
| 第一人称 | 用「我们」，把听众带进来；「我」用于个人经验 |
| 段落 | 2–4 句；一段一个意思，便于停顿 |
| 可以松的地方 | 重复（演讲中重复是节拍）、口语化过渡（"说白了""你想想"）、直接称呼 |
| 必须紧的地方 | ① 结尾的号召必须落在**具体动作**上，不许是纯语气 ② 数字只留 1–2 个关键的——念出来的数字听众记不住第三个 ③ 书面语连接词（"此外""综上所述"）必删 |

**反例**

> 各位同事，大家好。回首过去一年，我们共同经历了诸多挑战，也取得了令人瞩目的成绩。展望未来，我们充满信心。让我们以更加饱满的热情、更加昂扬的斗志，携手并进，共同开创更加美好的明天！

**正例**

> 说一件具体的事。去年这个时候，我们的交付周期是 45 天，客户骂了我们整整一个季度。今年是 31 天。这 14 天不是靠加班抢出来的，是靠把"等测试环境"这件事从流程里拿掉了——原来平均要等 6 天，现在测试环境是随用随起的。所以接下来六个月，我只盯一件事：把 31 天压到 25 天。具体怎么压，各组长周五之前把你们那一段最堵的地方写给我。

**差在哪**：反例三句话全是态度；正例给出了一个前后可比的数字，说明了它靠什么变化，并把下一步落到了"周五之前交什么"。

## 6. 公众号自媒体

**松紧规则**

| 维度 | 规则 |
|------|------|
| 结论位置 | **前 3 行**内给出钩子（结论检适用）。滑走发生在第 4 行 |
| 句长 | 短句，可碎；一句一行是允许的 |
| 第一人称 | 可用「我」，鼓励有个人经验 |
| 段落 | 1–3 句；段落短是移动端阅读的硬要求 |
| 可以松的地方 | 提问开头、第二人称直接对话、口语、小标题分段 |
| 必须紧的地方 | ① 不许用"随着…的快速发展"开头（首尾检）② 每个论点都要有具体的东西撑着（案例、数字、场景）——自媒体最容易退化成四字格连排 ③ 结尾不许"相信未来""让我们期待"（首尾检） |

**反例**

> 在当今这个快速发展的时代，健康的生活方式越来越受到人们的关注。拥有一个健康的身体，是我们追求一切美好事物的前提。那么，如何才能拥有健康的生活方式呢？今天，就让我们一起来探讨一下吧。首先，要注重饮食均衡。其次，要坚持适度运动。最后，要保持良好的作息习惯。

**正例**

> 我连续加班三个月，体检报告上多了两个箭头。
>
> 医生看完没开药，只问了我一句话：你几点睡。我说一两点。他说那先别查别的了。
>
> 后来我把睡觉时间从一点半挪到十一点，别的什么都没改。三个月后复查，那两个箭头都没了。
>
> 运动、饮食、作息这三件事，对上班的人来说，只有作息是"不改就没有别的可谈"的。前两件你都能糊弄过去，睡眠糊弄不过去。

**差在哪**：反例是一篇可以套在任何健康话题上的通稿，三段之间没有推进；正例开头三行给了一个具体结果（体检报告的两个箭头），后面每一段都在补充上段没说的信息。

## 附：三段式与四字格的通用禁令

六种文体里最统一的失手方式是**四字格连排填补空隙**（对应检查 4、7）。判断标准只有一条：

> 把这个四字词换成"具体是多少 / 具体是什么"，你换得出来吗？
> 换得出来 → 一开始就该写具体的。
> 换不出来 → 这个词没有承担任何信息，删。

例：「匠心打磨，精益求精」→ 换成「这个版本改了 47 处，改动最多的是下单页少了 2 步」。
