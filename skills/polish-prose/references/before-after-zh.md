# 中文正反例库

> **硬约束：所有例子必须来自中文写作的真实场景。禁止使用英文语料的中译**（如外国统计局、外国地名、外国菜肴）——那些例子描述的是英文写作的毛病，对中文写作没有诊断价值。
>
> 这条约束写在文件里，是因为**例句库是整套方法论唯一可能退化成 humanizer 老路的地方**：一旦例子开始从英文材料翻译过来，检查项就会重新变成"标题大小写""破折号使用"这类中文里根本不成立的条目。
>
> 本库的例子服务于「AI 特征表」，**不是改造标准**：检出 ≠ 必须消除。每个例子的重点是**怎么认出这个特征、认出之后作者面临什么选择**——「改后」一栏给的是其中一种走法，不是标准答案；有若干组例子处理的结论干脆是**不改**。

每组含五栏：**场景 / 原文 / 改后 / 命中 / 说明**。「命中」栏写的是「AI 特征表」（见 `polish-prose` 与 `write-prose` 两个 SKILL.md 的「核心方法论：AI 特征表」小节）中的特征名。

场景一律写清楚是哪一种写作（周报、技术方案、公众号文案、演讲稿、邮件、调研报告、通知、述职、复盘、JD、客服回执……），因为同一个毛病在不同文体里的正确处理不同。

## 一、转折的滥用（AI 最硬的指纹）

转折本是稀缺资源。一段话里真正需要"拐弯"的位置并不多；转折标记用得密，多半是在拿它制造论述感。

**认法**：「然而 / 但是 / 不过 / 却 / 反而 / 事实上 / 值得注意的是」这类标记出现频率明显偏高；或一段之内多个转折标记叠用。

**注意**：这一条抓的不是"转折词数量"，是**每一次转折有没有带来新信息**。下面有若干组的结论是"不删转折，改排布"。

### 1.1 场景：技术方案（连续转折——每节都拐一次）

- **原文**：①「Redis 性能最好，但是运维成本高。」②「本地缓存改造成本最低，但是它没法跨实例共享。」③「CDN 能挡住大部分静态请求，然而动态接口的命中率只有 12%。」
- **改后**：三处转折都不删。改的是**排布**：把三句权衡收进一张对照表（方案 / 延迟 / 运维成本 / 局限），正文只留一句结论「动态接口走 Redis，静态走 CDN，本地缓存不做」。
- **命中**：转折的滥用（连续转折）
- **说明**：这是**检出后不改转折本身**的例子。判据不是"转折多"，而是"每次转折是否带来新信息"——三处都带来了，删掉反而丢信息。要改的是它们的排布制造出的"每节都要拐一下"的节拍。

### 1.2 场景：公众号文案（为转折而转折）

- **原文**：很多人以为选跑鞋要看缓震，但其实鞋楦宽度才是决定磨不磨脚的关键。不过话说回来，缓震也不是不重要。然而对大多数业余跑者来说，每周跑量不到 30 公里，缓震的差异根本感觉不出来。
- **改后**：选跑鞋先看鞋楦宽度——它决定磨不磨脚。缓震排第二：每周跑量不到 30 公里的人，感觉不出各家缓震的差别。
- **命中**：转折的滥用（为转折而转折 + 一段内堆叠）
- **说明**：四个转折标记里只有第一处有真实的对照关系。后面两处是作者在"往回找补"——怕话说绝对，就加一个"不过""然而"退半步。改后让步的意思由"排第二"承担，不再需要转折词。**这类"找补式转折"是最容易被模仿、也最容易露馅的一种。**

### 1.3 场景：周报（转折代替论证）

- **原文**：本周接口联调进度不及预期，但是我们已经找到了问题所在。不过修复方案还需要和对方确认。虽然风险仍然存在，但整体可控。
- **改后**：接口联调没按计划完成，卡在对方返回的字段少了 3 个。修复方案今天发过去了，等他们确认。如果周五前没回，下周一的上线顺延。
- **命中**：转折的滥用（转折代替论证）
- **说明**：三处转折后面跟的都是形容词性质的短语（找到问题、需要确认、整体可控），没有一个可验证的事实。**把转折词遮住再读一遍**——句子马上空了一半，这个"空了一半"就是检出信号。补上事实，转折自然消失。

### 1.4 场景：产品说明（一段之内多个转折标记堆叠）

- **原文**：这个功能虽然看起来简单，但实际上背后涉及了复杂的权限校验逻辑，不过用户并不需要关心这些，然而对管理员来说，配置项还是需要了解的。
- **改后**：这个功能对普通用户只有一步：点导出。管理员那边多一层：要先把导出范围配好——配错了会导不出数据。
- **命中**：转折的滥用（一段四标记）
- **说明**：六十个字里塞了"虽然 / 但实际上 / 不过 / 然而"四个。可行的改法是**按读者拆句**：普通用户一句，管理员一句。转折消失是拆句的结果，不是目的——先想清楚这段话里有几个读者，转折往往是"没想清楚对谁说"留下的痕迹。

### 1.5 场景：演讲稿（口语中的转折）

- **原文**：我知道大家最近很累。但是我们不能停下来。因为我们身后没有人替我们扛。但是我也知道，光靠拼是不够的。所以接下来，我们要换个打法。
- **改后**：保留第一处"但是"，删掉"但是我也知道"。（念出来：我知道大家最近很累。（停）但停不下来——身后没人替我们扛。光拼不够，接下来换个打法。）
- **命中**：转折的滥用（口语转折）
- **说明**：演讲里的转折有节奏功能，"但是"可以是重音落点。**文体允许的就不算特征**：真人口语里偶尔的转折是停顿，不是论述感的装饰。被删掉的是第二处——"但是我也知道"是书面连接词，念出来不像人话。这一组的处理完全取决于文体：同一段话放进书面报告，两处都得重写。

### 1.6 场景：调研报告（转折引出的是常识）

- **原文**：调研中我们发现，一线员工更倾向于使用纸质单据。然而，这一现象并非偶然。这背后反映出的是流程设计上的深层问题。
- **改后**：调研中我们发现，一线员工更倾向用纸质单据。问下来原因很具体：系统里改一个数量要跳三个页面，纸上一笔画掉就行。
- **命中**：转折的滥用（转折引出常识）
- **说明**：「然而，这一现象并非偶然」不携带任何信息——没有哪个现象是"偶然"的。这类转折是**用转折的姿态冒充分析**。删掉它之后，后面那句"深层问题"也必须落到具体那件事上，否则整段仍然站不住。

### 1.7 场景：邮件（谈判语境下转折堆在结论前）

- **原文**：关于贵司提出的账期调整，我们内部做了沟通。虽然我们理解贵司的资金压力，也确实希望长期合作，但是考虑到我们自身的现金流安排，不过我们还是愿意做一部分让步，但是幅度可能有限。
- **改后**：账期可以调，从 60 天改成 45 天，再长我们这边排不开。这是现有现金流下能给的幅度。
- **命中**：转折的滥用（连续让步）
- **说明**：三处转折把"愿意让"和"只能让一点"来回拉扯，收件人读完不知道结论是什么。改后先给数字再给限制条件——**让步与限度各说一次**，不靠转折词分层。这类邮件的读者只想知道"行不行、到哪一步"。

### 1.8 场景：项目复盘（"事实上 / 真正的是"连续出现）

- **原文**：我们原以为瓶颈在数据库。事实上，压测数据显示数据库的 CPU 只到 40%。真正的问题在网关的连接池配置。事实上这个配置从上线起就没改过。
- **改后**：我们原以为瓶颈在数据库，压测结果显示它 CPU 只到 40%。真正的问题在网关——连接池上限还是上线时的默认值 200。
- **命中**：转折的滥用（纠偏句式重复）
- **说明**：「事实上」本身是好词，第一次用有纠偏作用。等它第二次出现，读者已经预期你要纠偏了，它就不再提供转折，只剩节拍。改后第二处直接用破折号带出事实。**这一条的信号是"同一个纠偏词出现两次以上"。**

### 1.9 场景：公众号文案（每节同位置一个"但"）

- **原文**：①「这个方法能省一半时间。但前提是你要先有历史数据。」②「历史数据不需要很全。但至少要有最近三个月。」③「三个月的数据够跑出初步结论。但要记得每月回看一次。」
- **改后**：这个方法能省一半时间，前提是要有历史数据——不用很全，最近三个月就够，够跑出初步结论。另外每月回看一次。
- **命中**：转折的滥用（节间节拍同构）
- **说明**：问题不在单个"但"，而在**三节同位置、同功能的"但"**：每节都是"给结论 → 但 → 加条件"，读起来像模板填空。合并成一段、条件用破折号串起来，节拍就散了。注意这一组也可以有另一种走法——如果三节本来就要分开讲，那就把其中一节的"但"换成正面陈述。

### 1.10 场景：申请文书（转折构成全段骨架）

- **原文**：我的本科成绩并不突出，但我从未放弃对这门学科的兴趣。虽然起步比别人晚，但我用了两年时间补上了基础。尽管过程艰难，但我从中获得了真正的成长。
- **改后**：我的本科成绩不好，起步也比同届晚两年。我把那两年用来补基础：旁听了四门研究生课，把导师组里的数据清洗工作接了下来。这段经历让我知道自己能靠笨办法追上来——这是我到现在唯一确信的事。
- **命中**：转折的滥用（转折撑起排比）
- **说明**：三个"虽然 / 尽管…但…"是这类文书的通病：**每一句的力度都来自转折，去掉转折就不成立**。真正的改法不是删转折，是**把转折后面的东西写实**。写实之后剩一处转折反而有力——它成了全段唯一一次拐弯。

## 二、比较的滥用

比较是论证手段，不是论证本身。每一节都要靠对照撑着，说明每一节都没有自己的推进。

**认法**：「不是 X 而是 Y」「X 比 Y 更…」「越…越…」「A 有…，而 B 则…」这类句子密度过高；或连续 ≥3 个小节拿同一个对象作对照。

### 2.1 场景：技术方案（连续对照同一对象）

- **原文**：①「新链路的写入延迟是毫秒级，而老系统是秒级。」②「新链路支持水平扩容，而老系统只能纵向升配。」③「新链路的故障隔离到分区，而老系统一挂全挂。」
- **改后**：三节并成一张对照表（三行：延迟 / 扩容方式 / 故障隔离），表下一句「老系统在这三项上都无法靠改造追上」。
- **命中**：比较的滥用（连续对照同一对象）
- **说明**：连续三节拿老系统当靶子，读者读三遍同一件事：新的比旧的好。**这一条不是要你删掉比较**——比较数据要留，留成表；要改的是"每节都要再比一次"的结构。

### 2.2 场景：产品说明（"不是…而是…"）

- **原文**：它不是一款记录工具，而是一个帮你理清思路的助手。它不是让你记得更多，而是让你想得更清楚。
- **改后**：它的用法是：把想到的东西先全部倒进去，再拖到一起看哪些是一回事。
- **命中**：比较的滥用（否定式定义连用）
- **说明**：「不是 X 而是 Y」是定义句的偷懒写法——它靠否定一个谁也没主张过的 X 来抬高 Y。改后直接给动作，读者自己会判断它是什么。（如果这句是产品定位的第一句、后面确有论证跟上，留着也无妨；**判据是它后面有没有兑现。**）

### 2.3 场景：公众号文案（"越…越…"）

- **原文**：越早开始记录，越容易发现规律；越早发现规律，越容易做出调整；越早调整，收益越大。
- **改后**：记录三个月，一般能看出周期；看出来了，调起来才有依据。
- **命中**：比较的滥用（递进式比较链）
- **说明**："越…越…"堆三层，语法上通顺，实际上是一条没有落点的链条——任何一件事都能这么写。改法是给一个**具体的量**（三个月）和一个**具体的用处**（调起来有依据）。

### 2.4 场景：竞品分析（每个维度都比一次）

- **原文**：在权限模型上我们比 A 完整；在报表能力上我们不如 B；在部署灵活性上我们优于 A 但弱于 C。
- **改后**：（表格：权限 / 报表 / 部署 × 我们 / A / B / C）表下写「可打的点是权限；要补的是报表——B 的交叉表我们做不了」。
- **命中**：比较的滥用（比较成为唯一内容）
- **说明**：整节没有一句不是比较句。比较是手段，结论才是内容。改后把"哪一项可以打、哪一项要补"单独写出来——那才是读者要的。也可以只留这张表和结论，删掉全部比较句——**两条路都行，取决于这份分析给谁看。**

### 2.5 场景：申请文书（以他人为坐标）

- **原文**：相比于同届的同学，我更早接触到真实项目；相比于只做研究的人，我更懂得工程落地。
- **改后**：大二暑假我在一家做仓储的公司待了两个月，写的是拣货路径的排程。那段经历让我第一次知道，算法在纸面上和在仓库里差在哪里。
- **命中**：比较的滥用（以他人为坐标）
- **说明**：「比同学更早」「比做研究的人更懂落地」把评价权交给了一个不存在的参照组——读者无从验证同届同学做了什么。**这类比较在文书里尤其伤**。改后换成自己做过的事：对比消失，分量反而更足。

## 三、判断的滥用

判断句的价值来自稀缺。每段都有金句，等于每段都没有。

**认法**：「这是…」「这正是…」「…是…的关键 / 前提 / 基础」「X 决定了 Y」密集堆积，尤其在段末形成"每段一句结论"的节拍。

### 3.1 场景：技术方案（每段末一句"是关键"）

- **原文**：①段末「数据一致性是这次改造的关键。」②段末「链路的可观测性是这次改造的关键。」③段末「回滚方案是这次改造的关键。」
- **改后**：删掉三句总结，把三件事写成并列的验收项——「上线前必须齐的三样：对账脚本、三个核心指标看板、一键回滚演练记录」。
- **命中**：判断的滥用（段末结论节拍）
- **说明**：三句都成立，所以三句都没用——一份方案里"关键"有三处，读者按哪一处排期？改成验收清单，优先级由顺序承担。**这里也可选择保留一处判断句**（最要紧的那一处），只要它不是三段里的第三句。

### 3.2 场景：公众号文案（金句连排）

- **原文**：选品不是选爆款，而是选你能持续供给的那一款。这是所有小店的生死线。库存结构决定了现金流，现金流决定了你能活多久。
- **改后**：小店选品只有一个约束：这一款你能不能稳定供上三个月。爆款断货一次，前面的推广费就白花。
- **命中**：判断的滥用（连续金句）
- **说明**：三句一句比一句像格言，读完却不知道明天该做什么。保留第一句的判断（它有具体所指），后两句删掉换成一次断货的实例。

### 3.3 场景：产品说明（"X 决定了 Y"）

- **原文**：响应速度决定了用户的留存意愿，而留存意愿决定了产品的商业价值。
- **改后**：现在列表首屏要 2.3 秒才出来，我们在测把它压到 1 秒以内会不会让次日留存动——这是这个季度唯一在做的实验。
- **命中**：判断的滥用（因果判断链）
- **说明**："决定了"是很强的断言，需要证据支撑；没有证据时，它还额外把话说死了。改后把断言换成一个正在做的实验——**不确定的事就用不确定的语气说**。如果作者手上有证据（做过 A/B），那就把证据补上，判断句反而成立。

### 3.4 场景：演讲稿（判断 + 自我注解）

- **原文**：教育是一棵树摇动另一棵树。这是我们的初心，也是我们走到今天的原因。
- **改后**：只留第一句。
- **命中**：判断的滥用（判断句加注解）
- **说明**：第一句是引用（**对引用一字不动**），第二句是给引用加注解。「这是我们的初心，也是…的原因」不增加信息，只让句子变长。删注解，保引用。

### 3.5 场景：项目复盘（段末"这暴露了…"）

- **原文**：①「延期两周，卡在第三方接口。这暴露了我们对外部依赖缺乏管理。」②「测试环境挂了两回。这暴露了我们对基础设施投入不足。」③「需求变更 5 次。这暴露了我们前期调研不充分。」
- **改后**：三件事照写，段末换成一次归纳，且必须落到动作上——「三次问题指向同一个动作：凡是有外部依赖的排期，都先把对方的交付时间写进计划表；写不出来的，不当成已确认。」
- **命中**：判断的滥用（段末结论同构）
- **说明**：「这暴露了…」连用三次，是**用概括代替分析**：三个"不足"都没有指向任何可改的动作。改后只在末尾归纳一次——判断句稀了，才有分量。

## 四、句式重复与句式单一

**句式重复**：同一句式结构在篇内反复出现。**豁免**：作者刻意设计的上下呼应、排比——那是有意为之，不是病。

**句式单一**：全篇句型集中，缺短句、独句、问句、插入语、停顿。

> 区分这两条要看**跨篇还是篇内**，也要看**删掉后力度是否变弱**。本节的例子有两条的结论是"不改"。

### 4.1 场景：公众号文案（"真正难的是…"）

- **原文**：同一篇里的三个小标题下各有一句——「真正难的是坚持」「真正难的是判断」「真正难的是取舍」。
- **改后**：**检出不改，前提是场景成立**。如果这三句分属同一天推送的系列文章，是刻意呼应；如果是同一篇里的连续三节，是句式重复。
- **命中**：句式重复
- **说明**：判断这一条要先问**跨篇还是篇内**。跨篇的三个标题隔天出现，读者感知到的是品牌感；同一篇里连着出现，读者感知到的是模板。

### 4.2 场景：调研报告（全是"从…来看"）

- **原文**：从成本来看……从交付周期来看……从团队适配度来看……从长期维护来看……
- **改后**：换掉其中三处——成本那段以数字开头（「一年 2 万，比 B 便宜 13 万」）；交付那段以问句开头（「三个月能上吗？A 可以，B 不行。」）；长期维护并进成本段末尾。
- **命中**：句式单一（引导语单一）
- **说明**：四个"从…来看"是同一句话换了四次头。改法不是找四个同义词，是**让每节用不同的方式开口**：数字、问句、结论各来一个。**这一条和「节间同构」相邻，区别在于那里改的是骨架，这里改的只是开口。**

### 4.3 场景：周报（全部"完成了…"）

- **原文**：完成了对账脚本联调；完成了监控项的补齐；完成了和财务的口径对齐。
- **改后**：对账脚本联调过了，卡在财务那边的科目映射，下周继续。监控补齐了 6 项，还差支付回调那条。口径的事开了个头。
- **命中**：句式单一（同一动词开头）
- **说明**：周报天然适合列表，但"完成了 X"连排会把"哪些没完成"藏起来——这是它比句式单调更实际的危害。混入状态句和未完成项，信息量立刻不同。

### 4.4 场景：演讲稿（通篇长句，没有落点）

- **原文**：一段两百字没有句号，中间靠多个"并且"连接。
- **改后**：三处"并且"改句号；在"这里我要说一句"之后加一个独立成段的短句。
- **命中**：句式单一（缺短句与停顿）
- **说明**：演讲稿的长句本身不是病，**连着两百字没有落点才是**——听众的耳朵需要换气。改法不是把句子切碎，是给三处落点。**书面稿按同一标准去拆，反而会拆坏。**

### 4.5 场景：演讲稿（排比）

- **原文**：我们守住了现金流，守住了客户，也守住了这支队伍。
- **改后**：**检出不改。**
- **命中**：句式重复（豁免）
- **说明**：判据是"这段重复删掉后，意思是否变弱"。排比删掉后力度明显下降 → 那是作者的手段，保留。**豁免条款保护的就是这种。**

### 4.6 场景：技术方案（长定语 + 无短句）

- **原文**：本方案通过对现有链路进行分层改造，在不影响线上流量的前提下，逐步将批处理任务迁移至实时通道，从而实现数据时效性从小时级到分钟级的提升。
- **改后**：这套方案分两层改，线上流量不动。批处理任务一批一批挪到实时通道。挪完之后，数据从小时级变成分钟级。
- **命中**：句式单一（长句无断点）
- **说明**：单看这一句，公文长句在技术方案里是允许的；**问题在于全篇都这样**。改后不是把长句切碎就行，是把"分层 / 一批批挪 / 结果"三件事分开说，句子自然变短。

## 五、空话与实词复用

**空话**的认法只有一问：**把这句话删掉，读者损失了什么信息？** 答得出 → 留着；答不出 → 是空话。

> **不给词表**：列出禁用词只会让措辞换一层皮——空话不会变少，反而多一层伪装。本节所有例子示范的都是"这一问怎么用"，不是"哪些词不能用"。

**实词复用**：同一实词（如"条件""结构""体系"）跨段反复出现。

### 5.1 场景：周报（判据怎么用）

- **原文**：本周在保障系统稳定运行的前提下，持续关注业务方的反馈，并在合适的时候推进优化工作。
- **改后**：删掉整句。删除清单里写清楚理由：**答不出"删掉后读者损失了什么"**——它没说关注到了什么反馈，也没说推进了哪件优化。
- **命中**：空话
- **说明**：这一组示范的是判据的用法：不是"这句里有'持续''合适的时候'所以是空话"，而是**先做删除测试，再下判断**。另外注意——如果作者确实在等业务方回话，正确改法是写「等业务方回话，预计周三有结果」，而不是删。**删除测试通过不等于必须删。**

### 5.2 场景：技术方案（读起来很专业，但删得掉）

- **原文**：在架构层面，我们始终坚持以业务价值为导向，兼顾技术先进性与落地可行性，形成了较为完整的能力体系。
- **改后**：删掉。如果确实需要一处收束，换成「这套架构的取舍标准：能用上的新技术才上」。
- **命中**：空话
- **说明**：「以…为导向」「兼顾…与…」「能力体系」是三处典型的"读完等于没读"。它们不像四字格那样扎眼，**正因为不扎眼才更难发现——只能用删除测试**。

### 5.3 场景：公众号文案（过渡句空转）

- **原文**：说完了选品，我们再来看看定价。定价是一个非常重要的问题。那么，小店的定价应该怎么做呢？
- **改后**：选品说完了，说定价。小店定价只有一个原则：跟着你的补货周期走，别跟着隔壁。
- **命中**：空话（过渡句空转）
- **说明**：中间两句删掉后读者损失为零。**过渡句只有在携带方向信息时才值得存在**——"选品说完了，说定价"携带了方向，所以留下；"这是一个非常重要的问题"什么都没携带。注意这一组也提示：过渡句的取舍跟文体的口语程度有关，口播稿里一句"那定价呢？"承担换气功能，可以留。

### 5.4 场景：述职报告（"体系"跨段复用）

- **原文**：全文 1200 字，"体系"出现 9 次，"机制" 6 次，"赋能" 5 次。
- **改后**：把其中 8 处"体系"落到具体名词上——审核规则 / 值班表 / 报价模板 / 供应商名单。剩下 1 处保留，它出现在结尾，确实指整个东西。
- **命中**：实词复用
- **说明**：实词复用的危险在于**它让作者以为自己说了什么**。"建了一套体系"读起来像有成果；写清楚是"值班表"，没那么体面，但那才是实际做的东西。**改法不是换同义词，是换回所指。**

### 5.5 场景：调研报告（同一个词指不同东西）

- **原文**：「渠道结构」「成本结构」「组织结构」「产品结构」——四段各出现一次，互相没有关系。
- **改后**：这四处的"结构"其实指四种不同的东西，分别改写成：渠道的层级 / 成本构成 / 汇报关系 / 产品线划分。
- **命中**：实词复用
- **说明**：这一条的重点不是"同一个词用太多次"，而是**同一个词在指不同东西**——那会让读者误以为它们可比。改法是把它们还原成各自的所指。

### 5.6 场景：邮件（礼貌性客套）

- **原文**：打扰您了，冒昧来信，如有不妥之处还请海涵。关于上次会议提到的报价，想跟您确认一下有效期。
- **改后**：**检出不改**（对外首次去信）。同一串邮件往来里第二次、第三次出现同一套客套 → 删掉。
- **命中**：空话（文体豁免）
- **说明**：**这一条必须按文体判断**。对客户、对外部、对上级的首次去信，开头的客气话有社交功能，删掉是失礼——此时它不是 AI 味，是礼节。内部同事之间、同一串往来里反复铺同一套客套，那才是空转。

## 六、节间同构与段长分布集中

**节间同构**：逐节写出骨架（如「论点 → 证据 → 对照 → 小结」），出现 ≥3 节同名骨架。作者的声音体现在结构选择上；每节一个模子，那是模板不是写作。

**段长分布集中**：长短段失衡，全篇段长落在相近区间。

### 6.1 场景：技术方案（每节都是四段式）

- **原文**：三节，骨架完全相同——现状痛点 → 方案设计 → 预期收益 → 风险提示。
- **改后**：**检出不改，如果这是评审模板要求的格式。** 若这份方案是要说服人而不只是过评审，把"预期收益"并进"方案设计"，并在最前面加一节"我们放弃的两种做法"。
- **命中**：节间同构
- **说明**：同构本身不是病——评审模板、立项书、安全评估这类文体**要求**同构，方便评审逐项对照。判断的落点是：**这个结构是文体要求的，还是作者顺手滑进去的。**

### 6.2 场景：公众号文案（三节同一骨架）

- **原文**：三节都是「你可能听过 X（否定）→ 其实是 Y（断言）→ 所以你要 Z（行动）」。
- **改后**：中段改成以读者提问开头；末段改成从一个具体案例讲起。
- **命中**：节间同构
- **说明**：三节同模，读者读完第二节就猜到第三节怎么走。**破同构最省力的办法是换开口**——一节用提问，一节用案例。改一两节就够，不必三节全改（全改会走到另一个极端：刻意的参差也是设计感）。

### 6.3 场景：调研报告（段长分布集中）

- **原文**：全文 24 段，每段都是 3 行，没有例外。
- **改后**：不是把段长随意打乱——先找出核心结论那一段（「选 B，因为…」），让它独立成段并加重；再把三处背景铺垫合并成一段。
- **命中**：段长分布集中
- **说明**：段长均等本身是排版习惯，**单独看不是特征**。信号在于它和内容不匹配：结论和铺垫占一样大，读者分不出轻重。改法永远是"让重要的那段变短或变重"，不是机械地拆合。

### 6.4 场景：周报（"总结 / 困难 / 计划"连用四周）

- **原文**：连续四周周报，每周都是这三节，每节都是三行。
- **改后**：这周只写一件事——接口联调卡了两周，写清楚卡在谁那里、下一步谁推。"困难"和"计划"这两节本周没有内容，直接不写。
- **命中**：节间同构 + 段长分布集中
- **说明**：周报模板最容易变成"填满四栏"。**判断标准是本周有没有这么多内容**，没有就留白。上面改后之所以成立，是因为内容真的只有一件；硬按四栏写满，就会滑回空话。

### 6.5 场景：演讲稿（每段以"我想说的是"开头）

- **原文**：六段，段段以"我想说的是…"开头，每段等长。
- **改后**：删掉其中四处"我想说的是"，直接在段首给出要说的那件事。
- **命中**：节间同构（段首句式同构）
- **说明**：和「句式重复」相邻，但这里问题更大——它连**段落的分界**都统一了，读者能听见模板在响。删掉三分之二的引导语，段落长度自然参差。注意：口播稿里留一处"我想说的是"有换气作用，全删反而像念稿。

## 七、无据断言

**认法**：断言追不到证据。

**处理**：**回去找证据**——不是停笔，也不是标个记号了事。

> **润色场景下不许替作者补数字。** 补数字属于新增事实，是 L2/L3 都不允许的越界；正确做法是交回作者（见 `polish-prose` 的「事实错误规程」）。下面每一组写的都是"这一步该往哪走"。

### 7.1 场景：公众号文案（"研究表明"）

- **原文**：研究表明，超过 70% 的人每天使用手机超过 8 小时。
- **改后**：不替作者补数。交回作者问一句：出处是哪份研究？找不到 → 换成作者能亲眼指认的样本（「我们后台看到的日活时长中位数是 6 小时 20 分」），或者整句删掉。
- **命中**：无据断言
- **说明**：数字越具体，编造越危险。「研究表明」没有指向任何一项研究。**这里最省事的错法就是当场换一个看起来合理的数**——那是润色场景明令禁止的动作。

### 7.2 场景：产品说明（"行业报告显示"）

- **原文**：行业报告显示，同类产品的平均响应时间是 200ms。
- **改后**：交回作者：报告名 + 机构 + 日期三要素齐全才能留。缺任何一项 → 换成自家可复现的数据（「我们实测 P50 是 180ms，压测脚本在仓库 bench 目录下」）。
- **命中**：无据断言
- **说明**：和 7.1 的区别在于**这里有一条更好的出路**——自己测得出来、别人复现得了的数据，比行业报告更有说服力，而且不需要引用权。

### 7.3 场景：调研报告（"多位专家认为"）

- **原文**：多位专家认为，该技术将在三年内成为主流。
- **改后**：三条出路，由作者选：①点名（谁、在什么场合说的）；②降级表述（「某厂商 2024 年技术白皮书预测该技术三年内成为主流（单一来源，未交叉验证）」）；③换成自己验证过的结果（「我们在实时风控场景已跑通，批量结算场景还不行」）。第三条通常最有力。
- **命中**：无据断言
- **说明**：「多位专家」是最典型的模糊归因。**这一条不能靠润色解决**——它是内容缺口，不是措辞问题，所以处理动作是"回去找证据"，不是"改一个说法"。

### 7.4 场景：项目复盘（"客户反馈良好"）

- **原文**：客户对本次交付非常满意，反馈良好。
- **改后**：去要证据——验收单签了字吗？有没有书面意见？复盘的证据载体是签字、工单、待办清单，不是形容词。同时提示作者：**真实反馈通常包含不满**，把不满写进去反而增加可信度（「验收单签了。另提了 3 条意见，'报表导出慢'被列为下个版本必须项」）。
- **命中**：无据断言
- **说明**：「反馈良好」不是断言过强，是它根本没有载体。这是"回去找证据"最直白的一组：**证据不在稿子里，在稿子外面。**

### 7.5 场景：演讲稿（"众所周知"）

- **原文**：众所周知，我们这个行业正在经历一场前所未有的变革。
- **改后**：先去掉"众所周知"——它是免举证的话术。然后看作者手上有什么：去年这条街上关了 4 家店、今年新开了 7 家其中 5 家同品类。样本量小，但它是真的。
- **命中**：无据断言
- **说明**：「前所未有」还多一层问题：它是无法验证的程度断言。**换成你亲眼见到的样本**，比"众所周知"有力，而且反驳不掉。

## 用法提示

1. **先定文体与用途，再看句子**。公文的程式化、论文的长定语、公众号的短句、演讲稿的口语重复——这些写法互相冲突，而且都正当。**文体允许的，就不是特征。**
2. **「改后」不是标准答案**。本表不规定怎么改，每一栏写的是"认出之后可以怎么走"。作者有别的走法（尤其是保真优先的那种）就按作者的来。
3. **检出不等于必须消除**。本库有若干组结论是"不改"——系列文案的句式呼应、排比、评审模板要求的节间同构、对外首次去信的客套。判断的唯一落点是：**读者能不能从这个特征认出"这是机器写的"。**
4. **不给词表**。空话与实词复用两组刻意不列禁用词——列出禁用词只会让措辞换一层皮，空话不会变少，反而多一层伪装。判断只靠"删掉这句读者损失什么"这一问。
5. **无据断言的处理是回去找证据**，不是标个记号了事；而润色场景下不许替作者补数字——交回作者。
6. **转折的滥用是优先级最高的一项**。它是 AI 最硬的指纹，也是最容易被误判的一项——判据是"每次转折有没有带来新信息"，不是"转折词多不多"。
