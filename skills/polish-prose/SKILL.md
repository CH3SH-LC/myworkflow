# 文稿润色

> **第一原则：保真优先于美。润色的目标是「让作者本来想说的话更清楚」，不是「变成我的文章」。**

任何一次改动，如果无法回答「这处改动让作者的哪句话更清楚了」，就不要改。

## 触发

- **必须触发**：已有成稿要修改（"太像 AI 写的""读起来别扭""太生硬""帮我改一下"）；只要问题清单不要改稿；对成稿做质量诊断。
- **不触发**：从零写作（→ 文稿写作）；只需核对事实与术语的技术文档审阅；代码与注释；翻译；纯问答。

**边界判据**：是否存在**用户认可的原稿**。没有原稿 → 走写作。灰区（半成品）→ 问一句：「保持你原文的立场和句子结构来改，还是可以按我的组织方式重写？」

## 改动分级

| 级别 | 做什么 | 授权 |
|------|--------|------|
| **L1 轻改**（默认） | 只动局部：改标点、换词、拆或合单句；不动句子顺序与段落结构 | 直接做 |
| **L2 中改** | 段内重排、合并或拆分段落、重写句子结构 | 直接做，但**不得新增事实、不得改变立场** |
| **L3 重写** | 重构全篇结构、重新组织论证顺序 | **必须用户明确授权** |

> **硬门禁：升档必须问，降档不必。**
> 用户说「帮我润色」而你判断需要 L3 → **停下问，不许默默重写。**
> 「润色」二字的默认授权是 L1；用户没说「可以重写」，你就不在 L3。

## 流程（4 阶段）

### 阶段 1：通读 + 写「不改清单」+ 全局诊断

**先读全文，再动手。** 然后写「不改清单」：3–5 处**「已经很好 / 明显是作者声音」**的地方，全程不动。

> **硬门禁：没有「不改清单」不许动手改任何一处。**
> 这份清单的作用是给你自己划一条"哪里是作者"的线——没有它，L1 会在二十处局部改动的累积中变成事实上的 L3。

进入阶段 1 之前先做长度判断：**≥2000 字** → 走下面的「大文本处理」。

**全局诊断**（先看结构层，不看句子）：结构是否支撑主旨？段落顺序是否推进？有没有哪一段放错了位置？诊断结果列成清单，先给用户看。

### 阶段 2：定级

按阶段 1 的诊断定 L1 / L2 / L3。要升级就**在此刻问**，不要改到一半才说。

### 阶段 3：改动

逐段过 AI 特征表，边检边改。三条约束贯穿全程：

1. **最小充分修改**——能改 5 个字解决的不改整句；能改一句解决的不改整段。
2. **不改判据**（见下）——即使命中特征也保留。
3. **信息守恒**——任何被删掉的信息，逐条记进「删除清单」。删掉之前想清楚：这条信息是冗余，还是只是"我写得更顺"？

不确定的改动 → 不擅自决定，做 A/B 两版（见「分歧呈现」）。

### 阶段 4：产出

交付「改后全文 + 四张清单」（见「产出物」）。若原文未命中任何特征、确实不需要改，**就直说**。

## 核心方法论：AI 特征表

> **维护注记**：本节「AI 特征表」与另一技能中同名小节必须**逐字一致**；修改其一时必须同步另一处。

### 先决：文体与用途

检任何东西之前，先明确：**这是什么文章、给谁看、要什么效果。**

公文的程式化、学术论文的长定语、公众号的短句节奏、演讲稿的口语重复——这些写法互相冲突，而且都正当。**本表所有判断以此为前提：文体允许的，就不是特征。**

### 用法

本表是**特征检出**，不是改造标准。

- 除第一条外，检出特征 **≠** 必须消除。作者刻意的强调、文体要求的程式，都可以保留。
- **本表不规定怎么改**——处理方式由你判断；本表只负责让你看见。
- 唯一的判据是：**读者能不能从这个特征认出「这是机器写的」。**

### 一、判断、转折与比较（默认禁止）

这三项是 AI 中文最硬的指纹，也是本表**唯一带硬性限额**的一组。不要等它们组成完整句式才认——**单个功能字用得太密，本身就是滥用**。

三者的判据是同一条，没有例外：

> **硬限额：每段至多 1 处。而且 1 处都嫌多——目标是接近零。**
> **唯一允许超出限额的情形：删掉它，全文会崩**（论点塌了、结论没了、读者接不上）。
> **单点检验：「把这一处删掉，全文是否崩溃？」不崩 → 删。**

**判断的滥用**
- 怎么认：`是` 是它的标记——「这是…」「…是关键 / 前提 / 基础」「X 决定了 Y」「…是…的」。**作系动词的纯叙述不算**，算的是下断言。
- 为什么：「判断句的力量来自稀缺」——它是全文最重的那几句。满篇判断，等于满篇都在喊结论，等于没有结论。

**转折的滥用**（三者中最硬的一条）
- 怎么认：`然而 / 但是 / 不过 / 却 / 反而 / 事实上`。单个字用得太密即算，不必组成完整句式。
- 为什么：转折是**承重结构**——真正需要转的地方极少。用得密，是拿它制造"论述感"：看起来在推进，其实只是在绕。

**比较的滥用**
- 怎么认：`比 / 更 / 最 / 而 / 则 / 相比 / 对比之下`。注意区分真比较与构词——「对比之下」是标记，「比如」「加勒比」不是。
- 另有**结构层**：连续 ≥3 个小节拿同一个对象作对照。这一条同样要过上面的检验——整节的对照必须是论证本身，不是装饰；做不到就不许有。
- 为什么：比较是论证手段，不是论证本身。每一节都要靠对照撑着，说明每一节都没有自己的推进。

### 二、句式

**句式重复**
- 认法：同一句式结构在篇内反复出现。
- **豁免**：作者刻意设计的上下呼应、排比——那是有意为之，不是病。

**句式单一**
- 认法：全篇句型集中，缺短句、独句、问句、插入语、停顿。

### 三、词汇

**实词复用**
- 认法：同一实词（如「条件」「结构」「体系」）跨段反复出现。

**空话**
- 认法：**把这句话删掉，读者损失了什么信息？** 答得出 → 留着；答不出 → 是空话。
- **不给词表**：列出禁用词只会让措辞换一层皮——空话不会变少，反而多一层伪装。判断只靠上面那一问。

### 四、结构

**节间同构**
- 认法：逐节写出骨架（如「论点→证据→对照→小结」），出现 ≥3 节同名骨架。
- 为什么露馅：作者的声音体现在结构选择上。每一节一个模子，那是模板不是写作。

**段长分布集中**
- 认法：长短段失衡，全篇段长落在相近区间。

### 五、证据

**无据断言**
- 认法：断言追不到证据。
- 处理：**回去找证据**——不是停笔，也不是标个记号了事。

### 修正记录

> 修正记录（2026-09-17）：**本节整体重写**。原「中文十二检」的十二条规范全部废弃（密度检、主语检、翻译腔检、具体检、主题句检、推进检、节奏检、骨架检、结论检、首尾检、标题检、篇幅检）。
> 废弃理由：原版把**通用写作规范**当成了 AI 特征——那些条目跟 AI 味无关，任何写作课都会讲，占满篇幅却抓不住真问题；而真正该抓的三处方向全偏（翻译腔去抓代词与被动，真凶是过量的判断与转折；节奏检去数句长，真凶是句式与设计上的重复；骨架检让人停笔，正解是回去找证据）。更根本的是：十二条硬阈值构成一个固定目标形态，把不同文本推向同一副面孔，**本身就在制造新的 AI 味**。
> 本版原则：**只检出、不规定改法**；**不给词表**；一切判断以「先决：文体与用途」为前提。

> 修正记录（2026-09-17）：**「判断、转折与比较」独立成组，并定为硬性限额**。两轮修正叠加：① 原来只认完整句式，漏掉了真正的战场——`是` / `然而·但·却·反而` / `比·更·最·而·则` 这类功能字**用得太密本身就是特征**，故每项都分层到功能词层；② 原来的"数密度"标准仍然过松（三成的判断句都算通过），改为**默认禁止 + 唯一例外**——每段至多 1 处、且 1 处都嫌多，只有"删掉全文会崩"才允许超出。**这是本表唯一带硬性限额的一组**，其余特征仍是纯检出。

## 五条防「改完更差」机制

**① 不改清单**——动手前先写 3–5 处「已经很好 / 是作者声音」的地方，全程不动。**没有这份清单不许动手。**

**② 最小充分修改**——能改 5 个字解决的不改整句，能改一句解决的不改整段。改动量不是工作量证明。

**③ 不改判据**——以下即使命中特征也保留：
- 作者刻意的重复（强调、节奏、呼应）
- 口语、方言、语气词（"其实""说白了""嘛"）
- 专业术语的固定表达（"灰度发布""幂等""对账口径"）
- 引语的原文（**一字不动**）

**④ 分歧呈现**——不确定的改动给 A/B 两版让用户选，不替用户决定。格式：`原文 | A 版（改动更小）| B 版（更顺但偏离原句式）`。

**⑤ 禁止凑工作量**——原文未命中任何特征就直说「我找不到需要改的地方」，并**列出检查过的项**。为了显得在干活而制造的改动，是这一类工具最大的伤害。

## 信息守恒

> **任何被删掉的信息必须列入「删除清单」并经用户确认。**
> 这是「改完更差」最常见的成因：句子变干净了，但作者要说的东西少了一块。

删除清单里逐条写：删了什么原句、**这条信息在原文里承担什么作用**、为什么判断它是冗余。判断不了是不是冗余 → 不删。

## 事实错误规程

> **硬门禁——分两类处理，不许混淆：**
> - **错别字 / 语病 / 标点** → **直接改**。
> - **事实、数据、引语、结论** → **一字不动**，列入「待作者确认」清单，标明你怀疑的原因。
>
> **禁止把数字改成「看起来对」的值。**
> **禁止用「大约」「若干」「相关数据表明」掩盖你不确定的数字。**
> 若错误影响全篇结论 → **停下先问用户**，不要先改后说。

检出「无据断言」时，最省事的错法是当场替作者补一个数字——**润色场景下这个动作被禁止**。补数字属于新增事实，是 L2/L3 都不允许的越界；正确做法是交回作者（见上方「事实错误规程」）。

## 防踢皮球

> 若需重排 **>50% 的段落**，停下告知：「已超出润色范围，建议走文稿写作」，由用户决定。
> **禁止自行升级到 L3。**
> **禁止硬按 L1 交付一个你明知不好的结果**——"我只做轻改"不是回避结构问题的借口。

## 大文本处理

**≥2000 字**：

1. 先给**全局诊断**（结构层问题清单），不逐句看。
2. 逐段改，一段一交付。
3. **禁止一次性吐出全文**——那既让你无法逐段核对信息守恒，也让用户无法逐段确认。

## 产出物

| 产出 | 内容 |
|------|------|
| 改后全文 | L1 只给改动后的段落；L2/L3 给全文 |
| **改动对照表** | `位置 \| 原文 \| 改后 \| 理由 \| 级别` |
| **不改清单** | 阶段 1 写的 3–5 处，以及为什么不动 |
| **待作者确认清单** | 疑似事实 / 数据 / 引语错误，标明位置与你的怀疑 |
| **删除清单** | 每条被删信息 + 它在原文中的作用 + 判断依据 |
| **结构变更说明** | 仅 L3 需要：段落如何重排、为什么 |

## 完成标志

- [ ] 「不改清单」在动手前已写出（3–5 处）
- [ ] 改动级别已确定；升档已征得用户同意
- [ ] AI 特征表逐项已过，**未新增任何事实、未改变任何立场**
- [ ] 事实 / 数据 / 引语未被改动，已进「待作者确认」清单
- [ ] 删除清单完整；无未经确认的信息丢失
- [ ] 不确定处已给 A/B 两版
- [ ] 四张清单（+ L3 结构说明）齐全
- [ ] 若原文已合格：已直说「找不到需要改的地方」并列出检查过的项

## 反绕过红线

- 没有「不改清单」就动手改 → 硬门禁违规。
- 用户说「润色」而你把全文重写了一遍 → 越权升档，最严重的违规。
- 把疑似错误的数字改成你认为正确的值 → 润色场景禁止新增事实。
- 为了让改动显得有价值，把本来通顺的句子改头换面 → 凑工作量。
- 删掉了信息却没进删除清单 → 信息守恒破裂。
- 特征表只过了词汇层（最好判断的那几项），回避了句式与结构 → 逐项必须完整，缺项即未完成。
- 需重排 >50% 段落却硬按 L1 交付 → 应先告知用户"已超出润色范围"。
- 把作者刻意的重复、口语词、术语固定表达按 AI 特征表"改掉" → 违反不改判据。
