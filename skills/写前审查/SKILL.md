# Skill：写前审查 — 动笔前的准备工作检查

> **⚡ 连续工作流**：此 skill 是「myworkflow:写前审查 → myworkflow:具体写作 → myworkflow:章节审查」自动链的第一环。完成后**必须立即调用下一 skill，不得停下等待用户**。详见底部「连续工作流规则」。

## 触发场景
- 每次准备写新一章之前（必须执行）
- **用户直接要求开始写作时**（如"开始写下一章""写第X章"等）——自动触发本审查
- 长时间中断写作后重新开始
- 写完一个事件后准备进入下一个事件

## 必需要素
- 细纲已存在（`大纲/细纲/{事件名}-细纲.md` 中本章已定义）——如果不存在，本 skill 会引导创建
- 上一章已通过**章节审查**
- **指南/风格定位.md**：写前必须复查本章计划是否与本书专属风格、禁忌冲突——动笔前调整比写完后返工成本低

## 推荐要素
- 角色/ 中本章涉及的人物均已设定
- 设定/索引.md 可查阅
- **进度/重复性记录.md**：写前查阅——本章的核心策略/塑造事件/日常场景是否与已记录的内容重复？

## 前置强制步骤

> **核心原则：指南文件是本书的"宪法"。** 写前审查是动笔前的最后关卡——本章计划必须在此时与指南文件对齐，而非写完后才发现风格不符。

1. **读取本书指南文件**：读取 `指南/` 文件夹下所有文件，逐条对照本章计划：
   - `指南/风格定位.md` — 本章的情绪基调、语言风格、人物互动方式是否与文风定位一致？
   - `指南/核心卖点.md` — 本章是否体现至少一个核心卖点？
   - `指南/书籍禁忌.md` — 本章计划是否触犯任一条禁忌？
   - `指南/AI记忆卡片.md` — 快速过一遍，确认本章没有遗漏关键约束
   - `指南/特殊设定约束.md` — 本章涉及的设定是否有特殊约束需要遵守？
   → 如果本章有指南中明确禁止的写法 → 在动笔前调整计划
   
2. **读取 CLAUDE.md**：了解当前创作状态——确认本章确实是"下一章"，确认上一章审查状态

3. **读取已有细纲和大纲**：读取 `大纲/细纲/{事件名}-细纲.md` 和 `大纲/{卷名}-完整大纲.md`，确认本章的章节类型、剧情走向、必须提到的内容、结尾钩子、所属小事件、大事件的大高潮标注

4. **个性化调整**：
   - 如果指南要求"每章至少一个小剧场" → 确认本章是否规划了小剧场
   - 如果指南要求"战斗时切换严肃" → 确认战斗场景的情绪基调是否正确
   - 如果指南禁止特定类型描写 → 确认本章没有越界

## 关联Skill

| 方向 | 关联对象 | 关系 |
|------|-------|------|
| 输入 ← | 本书个性化设计 | 写前检查本章是否符合5个指南文件（风格定位/核心卖点/书籍禁忌/AI记忆卡片/特殊设定约束）的全部要求 |
| 输入 ← | 大纲设计（细纲） | 细纲是写前审查的核心输入——章节类型、本章剧情走向、必须提到的内容、结尾钩子、所属小事件、小事件概览 |

| 输入 ← | 人物设计 | 检查本章人物是否都已设定（主要人物须含行为塑造四维/外貌与服饰/多标签融合） |
| 输入 ← | 明确设定 | 检查本章涉及的设定是否已定义 |

| 输出 → | 明确设定 | 如果新设定未定义，先调用补充 |
| 输出 → | 具体写作 | 通过审查后开始正式写作 |

## 目标
在每次动笔之前，通过两个阶段确保准备就绪：
1. **想清楚写什么**——与细纲联动，明确本章内容
2. **系统性审查**——检查人物/设定/时间线/前置状态

全部通过后才能开始写作。

---

## 执行流程

### 阶段一：想清楚写什么（与细纲联动）

#### 步骤1：检查细纲状态

**如果细纲已存在：**
- "阅读 `大纲/细纲/{事件名}-细纲.md`"
- "这次要写的是细纲中的哪一章？"
- "细纲中定义的本章内容是什么？一句话概括。"

> AI 根据细纲内容**自行判断**以下两项，无需提问用户：
> - 本章在情绪曲线上的位置（铺垫/发展/高潮/收尾）
> - 本章主导情绪（爽/紧张/感动/愤怒/期待/搞笑）
>
> **章节类型**直接读取细纲的 `章节类型` 字段（战斗类/日常类/过渡类/组合），无需判断。如有不确定，才向用户确认。

确认细纲中定义的本章结尾钩子："细纲中定义的本章结尾钩子是什么？"

确认细纲中标注的必须提到的内容："细纲中标注了哪些本章绝对不能遗漏的内容？（关键人物出场/退场、重要设定揭示、伏笔埋设/回收）"

**步骤1.5：细纲结构完整性速查**
- [ ] 细纲中是否包含 `小事件概览` 表？当前大事件的小事件构成是否明确？
- [ ] 当前大事件内是否标注了至少一个**小高潮**？（在 `小事件概览` 表或 `小事件构成` 行中确认）
- [ ] 本章所属小事件在概览表中的位置（过渡/核心/收尾）是否明确？
- [ ] 如果当前大事件在完整大纲中被标注为 ⭐大高潮事件 → 本章写作强度应达到全卷最高水平，确认已做好高强度写作准备（更多篇幅、更高情感强度、更充分的读者反应描写）
- [ ] 本章细纲条目本身的必填项是否齐全？——`章节类型`、`本章剧情走向`、`必须提到的内容`、`结尾钩子`、`所属小事件` 至少这五项不得为空
- [ ] **如果是新卷或新大事件的第一章**：开篇是否遵循了黄金三章逻辑？（信息量适中不倾倒设定、尽快抛出本章的核心看点、拒绝纯铺垫——读者翻开新卷/新事件的第一章需要立刻感受到"这一段值得追"）
- 以上任一项缺失 → 回到「myworkflow:大纲设计」补充细纲，再继续本审查

**如果细纲不存在：**
> ⚠️ **这不是正常流程。** 细纲应在写前审查之前通过「myworkflow:大纲设计 → 细纲层」独立完成。只有忘记或中断恢复等例外情况才走此路径。

- "这次要写的内容在细纲中有定义吗？"
- 如果没有→帮用户想清楚：

**启发式提问（帮助明确本章内容）：**
- "接下来这个剧情段/事件大概讲什么？"
- "如果把这个剧情段分成几章，本章是其中的哪一部分？"
- "本章的核心看点是什么？"
- "本章从哪里开始？（衔接上一章结尾）"
- "本章在哪里结束？（准备用什么钩子引到下一章）"

> 当用户回答完以上问题后，内容已经基本成形。
> **接下来必须调用「myworkflow:大纲设计」的细纲层级**，将上述内容写成正式的细纲文件。
>
> 为防止上下文丢失，调用前先**记录以下信息**：
> - 本章从哪开始（衔接点）
> - 本章核心内容
> - 本章结尾钩子
> - 本章涉及的人物和设定
>
> 写入细纲后，**继续当前写前审查**，从步骤2开始。
>
> ⚠️ 补完本次后，后续章节的细纲应在写前审查**之前**独立完成，不要再走此补写路径。

#### 步骤2：确认内容清晰度

- "如果用一句话向别人介绍这章的内容，能说清楚吗？"
- 如果说不能 → 继续追问，直到能一句话说明白为止

确认以上问题后进入阶段二。

---

### 阶段二：系统性审查

#### 审查项一：前置状态检查

- [ ] **上一章是否已通过「myworkflow:章节审查」？**
  - 如果上一章还未审查或审查未通过 → 应先完成上一章的审查，再动笔本章
  - 带着未审查的问题写下一章，会把问题越积越大
- [ ] 上一章审查中标注为"有条件通过"的改进项是否已处理？

#### 审查项二：人物检查

- "这章涉及哪些人物？"
- "这些人物的设定是否存在？（如有缺失 → 先调用「myworkflow:人物设计」独立模式补充）"
- **人物设定完整性检查**（仅针对**新出场的**或**本章首次大规模使用的**主要人物）：
  - [ ] **行为塑造（阶段C+）**是否已定义？动作特征/语言特征/神态特征/行为逻辑四个维度是否齐全？
  - [ ] **外貌与服饰风格（阶段B+）**是否已设计？面部特征/身体特征/服饰风格是否可查阅？
  - [ ] 如有**多个性格标签**：多标签融合（阶段C+ ⑤）是否已完成？主/副标签优先级和激活条件是否明确？
  - 以上任一项缺失 → 先调用「myworkflow:人物设计」独立模式补全，再继续本审查
- **逻辑进度检查**：
  - **物理状态**：角色的等级、伤势、关键物品是否与上一章结束时一致？
  - **情绪状态**：上一章的结尾情绪是什么？本章开场情绪是否自然衔接？（不能上一章刚痛失挚友、本章开头就在讲笑话）
  - **关系状态**：上一章中人物关系如果发生了变化（争吵/和解/新增矛盾），本章应延续这个状态
- "如果有新出场人物——类型（主要/临时/龙套）是否已确定？"

#### 审查项三：设定检查

- "这章涉及哪些设定？（查 `设定/索引.md` 快速定位）"
- "这些设定是否已在设定文件夹中有记录？"
- "准备引入新设定吗？→ 先写入设定文件再动笔"
- "本章是否会与已有设定矛盾？"

#### 审查项四：时间线检查

- "当前故事的时间点是什么？"
- "上一章结束时发生了什么？（有必要时重读上一章结尾）"
- "这次写作的时间线是否接续上一次的结尾？"
- "如果有时间跳跃，是否明确了跳跃幅度？"

#### 审查项五：重复性检查

**短距离审查（相邻小事件）**：本章所属小事件与上一个小事件在以下维度是否有显著区别？

| 检查维度 | 战斗事件 | 日常事件 |
|---------|---------|---------|
| 触发方式 | 主动出击 vs 被动遇敌 vs 救援 vs 伏击 | 计划中的活动 vs 意外相遇 vs 外部事件引发 |
| 敌人/对象 | 敌人类型/数量/策略是否不同？ | 互动的对象/主题/情绪基调是否不同？ |
| 环境 | 战场地形/天气/时间是否不同？ | 场景/时间/氛围是否不同？ |
| 结果 | 胜负平/撤退？是否与上次相同？ | 关系推进方向是否不同？ |

> **最低要求**：相邻小事件至少在以上两个维度上有显著区别。四个维度全部相似 → 向用户指出并建议修改。

**长线审查（跨事件）**：
- "查阅 `进度/重复性记录.md`——本章的核心策略/战斗策略/人物塑造事件/日常场景是否与已记录的内容重复？"
- "如果发现疑似重复 → 向用户指出（之前哪里用过、这次哪里相似）"
- "如果疑似重复属于\"允许的重复\"（前后呼应callback / 人物标志性行为）→ 向用户说明理由并确认：之前在哪里使用过、这次如何不同、为什么值得重复。未经用户明确批准，不得使用。"

#### 审查项六：风格定位检查

- "查阅 `指南/风格定位.md`——本章计划内容是否符合本书专属风格和禁忌？"
- "本章的情绪基调、语言风格、人物互动方式是否与文风定位一致？"
- "如果本章有风格定位中明确禁止的写法 → 在动笔前调整计划"

#### 审查项七：写作铁律与标点规范预检

> 以下为「myworkflow:具体写作」中定义的绝对不能犯的写作铁律。在动笔前预检这些规则，比写完后返工成本低得多。
>
> **写后强制验证**：本章写完后，「myworkflow:具体写作」第六步和「myworkflow:章节审查」审查项四均会强制运行以下自动化检测脚本。本审查项七是写前预检——确保构思阶段就不出现违规句式。写完后由脚本做最终机械性验证：
> ```bash
> python "$HOME/.claude/plugins/webnovel-studio/tools/chapter_check.py" <本章正文文件路径> --format json
> ```
> 该命令覆盖本审查项七中所有标点、句式、用词规则（17 项检测）。**写前在此预检违规项 → 动笔时主动避开 → 写完后脚本验证。** 如果脚本返回 `failed`，必须修改正文直到硬性规则项全部 `passed=true`。

**语言表达铁律预检**：
- [ ] **脏话控制**：本章是否规划了需要使用脏话的场景？脏话是否仅用于角色极端情绪（暴怒/绝望）的自然流露——而非作者加强语气的工具？
- [ ] **"不是…而是…"类转折句式**：本章构思中是否出现了"不是…而是…""不是…是…""不是…只是…""没有…而是…"等否定A→肯定B的句式？→ 出现即删，改为动作呈现
- [ ] **"和……一样……"类比较句式**：本章构思中是否出现了"和/跟/同/如同……一样……"等比较句式？→ 出现即删，用直接白描替代
- [ ] **"一样/不一样"及近义词**：预判本章动笔后是否会频繁使用"一样/不一样/同样/相同/不同/类似/似的/近似/无异/没什么两样/没什么不同"等词？（硬性上限：每章≤3次）→ 如果预感会超量，写前就规划用直接描写替代
- [ ] **对比/比较手法**：本章构思中是否出现了"与……不同""相比之下""而……却……""曾经……现在……"等对比标记？→ 出现即删，直接写当前场景的具体细节
- [ ] **比喻节制**：本章是否规划了用比喻的地方？→ 凡是能用白描替代的比喻，写前就决定用白描。一节最多1个比喻
- [ ] **纯文本输出**：是否已确认正文不使用任何 Markdown 格式标记？
- [ ] **破折号节制**：本章是否规划了破折号使用？（硬性上限：每章≤1处，仅限对话被外力打断）→ 写前就规划用句号/逗号/动作描写替代
- [ ] **"是"字判断句节制**：本章构思中是否出现了大量的"A是B""这就是X""那是Y"等判断句式？（硬性上限：每章叙述中 ≤2 处，对话口语/客观事实/强调句"是…的"不计）→ 预判会超量的话，写前就规划用动作/白描/具体细节替代

**人物塑造铁律预检**：
- [ ] 本章出场主要人物的**四维行为塑造**（动作/语言/神态/行为逻辑）是否已确认？
- [ ] 本章是否规划了至少一个展示性格的具体细节（独有动作/口头禅/习惯反应/微表情）？
- [ ] 本章构思中是否出现了"她是X的人""他性格X""他向来X"等直接性格描述？→ 出现即删，转为动作呈现
- [ ] 本章是否有角色首次出场？→ 是否规划了2-3个出场定型细节？
- [ ] 本章配角是否有独立于剧情的个性细节（不是"推动剧情的道具"）？

**结尾钩子预检**：
- [ ] 本章结尾是否已预选钩子类型（断章13式之一）？
- [ ] 钩子是否是情节自然发展的结果（非"天降神钩"）？
- [ ] 本章构思的结尾是否触犯9类禁止结尾（总结/收束/展望/感悟/口号/闭环/安静收尾/拖沓/补充）？
- [ ] 钩子句是否计划为本章最后一句（无追加解说/抒情/感悟）？

**标点符号规范预检**：
- [ ] 是否已确认中文段落使用全角中文标点（，。！？：；""''《》——……）——禁止英文半角点号、`...`/`。。。`替代省略号、英文直引号替代全角弯引号？
- [ ] **标点层级预检（重点——AI 默认每句都用句号结尾，必须主动对抗）**：是否已准备好用逗号连接分句而非频繁用句号断开？动笔前就建立"一段之内句号是例外，逗号是常态"的意识——逗号与句号之比应 ≥ 3:1。如果全文逗号数和句号数差不多 → AI 的默认坏习惯又犯了，必须回头修改
- [ ] 是否已确认中英文/数字混排处添加半角空格？
- [ ] 是否已确认排版禁则（行首不能出现，。、；：！？…》）》"】；行末不能出现"'《（［【；破折号/省略号不可断裂）并准备写完后扫查？

## 完成标志

- [ ] **写作内容明确**：知道写什么、从哪开始、到哪结束、用什么钩子

## 常见错误

| 错误 | 为什么错 | 正确做法 |
|------|---------|---------|
| 跳过审查直接开写 | 上一章未审的问题带入本章，两个问题同时解决 = 三倍工作量 | 写前审查是所有写作的必过关卡，没有例外 |
| 上一章审查"有条件通过"但改进项被忽略 | 小问题累积到第5章就不再小——累积债 | 条件通过的改进项在下一次写前审查中必须确认状态 |
| 审查发现缺少人物设定→先写再说，"写完了补" | 不知道人物设定的写作=写不准确的行为→后期大修 | 补充人物设定后再动笔 |
| 情绪状态不检查 | 上一章刚痛失挚友、本章开头在讲笑话=读者觉得角色没有心 | 核对人物上一章的结尾情绪，本章开场必须自然衔接 |
| 无细纲就进入写前审查（非例外情况） | 细纲是大纲设计的工作，不是写前审查的子步骤。反过来补是"没地图先上路再找路" | 写前审查前独立完成当前事件的细纲。写前审查的"无细纲"路径仅限例外 |
| 无细纲直接写 | 写到一半不知道为什么写这一章，钩子也想不出来 | 先调大纲设计补细纲 |
| 时间跳跃没有确认幅度 | 时间线混乱的根因——本章是"第二天"还是"一周后"没想清楚就写 | 明确时间跳跃的幅度，记录到时间线 |
| 跳过写作铁律预检 | 构思中出现"她是个懒散的人""使用Python"等违规模式，写前未拦截——写完后返工成本高 | 审查项七必须执行：语言表达铁律/人物塑造铁律/结尾钩子/标点规范全部预检 |
| 构思中用英文标点/省略号 | 动笔前构思时就用"..."或英文逗号——带着这个习惯写正文会把错误带进去 | 写前就切换到中文标点思维——构思时脑中就用"……"和"，" |
| 结尾预检被跳过 | 写完发现结尾是总结式/收束式，整章需要大修 | 动笔前对照9类禁止结尾排查本章计划——如果计划中的结尾触犯任一类，写前就换方式 |

## 危险信号 — 停下先处理

- "写前审查？我脑子已经想好了不用走流程" —— "想好了"不能替代系统检查。15分钟审查 vs 3小时改文，选择前者
- 上一章审查结果是❌不通过，但用户要求直接写下一章 —— 拒绝。未通过审查不能进入下一章（闭环纪律）
- 细纲中本章内容只有一句话概括，用户也说"差不多就行" —— 内容不清晰时写的每一段都可能要废
- 连续三章写前审查都跳过人物/设定检查 —— 这三章中至少有一章藏着一个隐含矛盾
- 构思中出现了"她是个懒散的人""他这么做不是因为恐惧，而是因为愤怒""她的眼睛和星星一样明亮"等句式 —— 写作铁律违规在构思阶段就出现了——写前立即调整为动作/白描呈现
- 构思中计划用"夜色渐深，一切归于平静"收尾 —— 这是"关灯睡觉"的禁止结尾——写前就替换为钩子
- 动笔前就在构思中用"..."代替省略号或用英文引号 —— 标点习惯在写前就已出错——切换到全角中文标点思维后再动笔
- 构思中每句话都以句号结尾（"他推开门。房间里没人。桌上有一封信。"）——AI 的默认坏习惯在构思阶段就暴露了——动笔前就在脑中用逗号连接分句，建立"一段之内句号是例外"的意识
- 构思中出现了大量"他是X的人""这就是Y的关键""那是Z的转折点"等"是"字判断句 → "是"字句泛滥在构思阶段就已出现——写前规划用动作/白描替代，预判超量时提前向用户申请批准

## 审查未通过的处理方式

| 问题 | 处理 |
|------|------|
| 无细纲 | 提问明确本章内容 → 调用**大纲设计**写入细纲 → 继续当前审查 |
| 上一章未审查 | 先行调用**章节审查**审查上一章 → 通过后返回 |
| 缺少人物设定 | 调用**人物设计**独立模式补充 → 返回当前审查 |
| 设定未定义/矛盾 | 调用**明确设定**补充 → 返回当前审查 |
| 时间线不连续 | 查看 `进度/时间线.md`，修正理解 → 继续 |
| 细纲结构不完整（缺小事件概览/小高潮/必填项等） | 回到**大纲设计**补充或修正细纲 → 继续当前审查 |
| 写作铁律预检失败（构思中存在禁则句式/禁则结尾/标点错误等） | 在审查项七中调整——构思阶段就修正违规内容，不要带到正文中 |

全部通过后 → **立即使用 Skill 工具调用「myworkflow:具体写作」开始写作。不要停下来询问用户是否继续。**

## 连续工作流规则（CRITICAL）

> **此 skill 是「myworkflow:写前审查 → myworkflow:具体写作 → myworkflow:章节审查」连续工作流的第一环。**
>
> - 审查通过后，**必须立即自动调用「myworkflow:具体写作」skill**，不得停下来等待用户确认
> - 如果审查未通过（缺细纲/缺人物设定/上一章未审查等），先修复阻塞项，修复后**仍然自动继续**调用具体写作
> - 唯一需要停下询问用户的情况：细纲不存在且无法自动补写（需要用户决策剧情走向）
> - 更新 CLAUDE.md `当前创作状态` 为"写前审查通过 → 写作中"
