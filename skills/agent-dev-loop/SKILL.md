## 触发

- **必须触发**：创建/修改/删除代码或文件、加功能、重构、新增、改写；**发现 bug 需修复**；对话中途随口提出的产出需求；"继续/接着做"（本 skill 已触发且任务未完成时）。
- **不触发**：纯问答、文件阅读/搜索、纯格式化/注释、闲聊不写代码、纯根因排查（只查不修，走 `root-cause-analysis`）。

## 目标

每次开发走完整闭环：**需求理解 → 计划制定 → 执行实现 → 真实验证 → 问题循环**。禁止跳步、禁止伪验证（仅跑单测）、禁止发现问题后不回头修复。

## 主线（5 阶段，不可跳）

### 阶段 1：需求理解
读 CLAUDE.md 与相关代码；复述核心目标/输入/输出/约束；模糊点用 AskUserQuestion 追问（最多 3 轮，每次一问）；复杂或意图不明 → `Skill("myworkflow:req-clarify")`。确认后进阶段 2。

### 阶段 2：计划制定
产出分步清单 + 验证方案（以用户身份验证，不写"跑测试"）+ 风险点。**跨文件或 ≥2 独立模块 → 计划标注"阶段 3 派发子智能体"**。展示计划获批准后进阶段 3。

### 阶段 3：执行实现
1. **拆解派发**：跨文件/多模块 → `Skill("myworkflow:task-dispatch")` 派发，完成后 `Skill("myworkflow:integration-verify")` 验证接口合规；否则直接实现。
2. **TDD**（新增/修改逻辑必须；文档/配置/静态资源跳过）：先写失败测试 → 最小实现 → 重构。
3. **遇到 bug 不盲目改**：调 `Skill("myworkflow:root-cause-analysis")` 定位根因（只查不修）→ 按报告根因修复 → 继续。
4. **自检**：计划步骤全完成、TDD 全绿、无语法/import 错误。

### 阶段 4：真实验证（硬门禁）
1. **前置**：阶段 3 所有 TDD 全绿；有失败回阶段 3 补完。
2. 调用 `Skill("myworkflow:real-world-verify")`，传入：项目根目录/类型、变更概要、启动命令、测试命令、关键用户路径（≥5 条）。
3. **核心原则：TDD 全过 ≠ 功能完成。** TDD 测"代码按预期运行"，真实验证测"用户按预期使用"，缺一不可。

### 阶段 5：判断与循环

```
验证全过 → 完成
有 ❌ → 小（几行可修）→ 回阶段3；中（动设计不改需求）→ 回阶段2；大（方向根本错）→ 回阶段1
```

每个 ❌ 必须处理，不允许降级跳过；**≤3 轮完整循环**，3 轮后仍有问题 → 停下上报用户。

## 后置步骤
1. 报告验证结果与产物。
2. 提交远程（commit/PR/merge）→ `Skill("myworkflow:github-collab")`。

## 完成标志
- [ ] 需求已确认、计划已批准
- [ ] 代码按计划产出（跨文件已派发 + 集成验证）
- [ ] 阶段 4 真实验证完成（happy path + 边界 + 回归）
- [ ] 所有 ❌ 已循环修复（≤3 轮）
- [ ] 结果已报告用户

## 元使用：审计模式
任务为审计/优化 skill 时：明确审计目标与维度 → **派子智能体审计**（作者盲区只有新鲜视角能发现）→ 读报告，P0/P1 各项 = 验证场景 → 自动循环修复，**P0/P1/P2 全部清零才停止**（≤3 轮）。
