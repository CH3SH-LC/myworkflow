# Skill：大纲设计 — 四层大纲体系

## 触发场景
- 首次规划全书（粗纲）
- 进入新分卷/新阶段时规划事件（完整大纲）
- 准备写某个事件前拆解章节（细纲）
- 管理已埋伏笔或规划新伏笔（伏笔管理）
- **以上四个层级可按需单独触发，不需要每次走全流程**

## 必需要素
- 粗纲层：无硬性前置（但推荐有基础设定和人物概念）
- 完整大纲层：粗纲中已有对应分卷的规划
- 细纲层：完整大纲中已有对应事件的规划
- 伏笔层：正文已开始写作
- **指南/风格定位.md**：本书的风格定位影响大纲节奏——必须在设计前读取，设计全程遵守

## 推荐要素
- **设定/（战力体系、世界规则）**：大纲中的事件必须符合世界规则（这个世界能发生什么、不能发生什么）
- **角色/（主要人物设定）**：已有角色是编排事件的基础——事件服务于人物弧光

## 前置强制步骤

> **核心原则：指南文件是本书的"宪法"。** 大纲的节奏、事件调性、高潮设计必须服从指南文件中的风格定位——轻松文风不宜设计过长的压抑期，严肃史诗不宜插入过于跳脱的轻松章。

1. **读取本书指南文件**：读取 `指南/` 文件夹下所有文件，特别关注：
   - `指南/风格定位.md` — 本书整体基调 → 决定大纲节奏（快节奏/慢热/混合）和事件调性
   - `指南/书籍禁忌.md` — 大纲中的事件不能违反
   - `指南/特殊设定约束.md` — 是否有约束大纲设计的特殊设定
   → 如果 `指南/` 文件夹为空或仅有基本骨架 → 提示用户先调用「myworkflow:本书个性化设计」完成指南文件的深度定制
   
2. **读取 CLAUDE.md**：了解当前创作状态、当前写作位置、已有大纲层级、结局方向

3. **读取已有大纲**：检查 `大纲/` 文件夹下已有的大纲文件，确认当前需要哪一层级

4. **个性化调整**：
   - 如果指南要求"轻松幽默为主" → 粗纲中不宜设计过长的压抑期或残酷事件
   - 如果指南要求"快节奏" → 完整大纲中前30章内必有第一个大高潮
   - 如果指南有明确的篇幅要求 → 粗纲的分卷和章数规划需匹配
   - 如果指南有禁止的桥段类型 → 大纲中完全排除

## 目标
帮助用户建立四层大纲体系：粗纲（全书走向）→ 完整大纲（分卷事件）→ 细纲（章节划分）→ 伏笔（长线管理）。

## 使用方式

按需触发，可选单层级：

- **触达粗纲**：项目启动时或全书方向调整时
- **触达完整大纲**：进入新分卷时
- **触达细纲**：准备写某个大事件时
- **触达伏笔**：定期检查或管理伏笔时

> 每次只跳转到需要的层级。

**层级依赖守卫**：粗纲 → 完整大纲 → 细纲 的依赖链不可跳过。
- 触达完整大纲前：检查 `大纲/粗纲.md` 是否存在。如不存在 → "完整大纲需要粗纲作为锚点。请先完成粗纲层的规划。"
- 触达细纲前：检查对应分卷的 `大纲/{卷名}-完整大纲.md` 是否存在。如不存在 → "细纲需要完整大纲中的事件定义。请先完成对应分卷的完整大纲。"
- 触达伏笔前：检查正文是否已开始写作（至少完成第 1 章）。

## 层级一：粗纲 — 全书骨架

**尺度**：全书层面，百章/分卷级别。
**文件位置**：`大纲/粗纲.md`（全书仅一个文件）

### 启发式提问

#### 第一轮：结构化问卷（使用 AskUserQuestion）

> 使用 `AskUserQuestion` 工具一次性发送以下问题。用户提交后，根据回答进入文本追问。

**Q1** | header:"预计篇幅"

- "50万字 (~200章)": 中短篇，聚焦单一主线
- "100万字 (~400章)": 中长篇，主线和重要支线并行
- "200万字 (~800章)": 长篇，多分卷多层次展开
- "300万字+": 超长篇，世界观和人物群像全面铺开

**Q2** | header:"节奏类型"

- "快节奏": 前30章内必有第一个大高潮，节奏紧密
- "慢热型": 前期铺垫充分，中后期爆发
- "混合型": 每卷内部有起承转合，卷与卷之间节奏交替

**Q3** | header:"分卷规划"

- "3卷": 精炼结构，起-承-合
- "5卷": 标准长篇结构，每卷有独立主题
- "7卷": 丰富展开，各卷侧重不同支线
- "10卷+": 超长篇群像，多势力多线并行

**Q4** | header:"结局收束"

- "全收束": 所有线索收拢，每个主要角色有明确终局
- "开放式": 留白，给读者想象空间
- "为续作留口": 主线完结但世界观保留，可能出续作

> 用户提交后，进入文本追问。

#### 第二轮：纯文本追问

##### 全书定位展开
- "每卷的核心主题是什么？"
- "故事从起点到终点经历了哪几个大阶段？"
- "每个阶段的核心目标是什么？"
- "每个阶段的终点在哪里？"

##### 结局方向展开
- "故事最终怎么收尾？主角的结局状态？主要反派/配角的结局？"
- "如果现在还没有明确想法——先标注『待定』。但建议在写完第一分卷后重新回答这个问题。"
- 理由：有方向不等于锁死，但完全没有方向会在中期迷失。

##### 节奏分配展开
- "哪个阶段是铺垫期？哪个阶段是高潮期？"
- "前30章内读者能看到第一个大高潮吗？"

### 输出格式

```
# 粗纲：{小说名}

## 全书信息
- 预计总章数：XXX章 / XXX万字
- 分卷数量：X卷

## 结局方向
- {结局设想 / ⚠️ 待定（建议第一分卷完成后重新讨论）}

## 阶段规划
### 第一卷：{卷名}（第1-XX章）
- 核心主题：
- 主角状态：
- 结束标志：
```

> **关联提醒**：粗纲中规划的"主角状态"变化（如晋级、获得关键物品），必须符合**设定/战力体系.md**中的等级规则。

## 层级二：完整大纲 — 分卷事件设计

**尺度**：一卷之内，事件级别（一个大事件通常20-100章，小事件2-5章）。
**文件位置**：`大纲/{卷名}-完整大纲.md`

### 启发式提问

- "这一卷的核心目标是什么？"
- "这一卷由哪几个大事件组成？"
- **"这一卷的大高潮在哪里？"**（必答——没有大高潮的分卷 = 读者不知道这一卷为什么存在）

对每个大事件：
- "起止章节范围是什么？占本卷多少篇幅？"
- "该大事件在本卷中的作用是什么？（推进主线/塑造人物/引入设定/铺垫高潮/大高潮）"
- "该大事件的小高潮在哪里？"
- **衔接检查**："一个大事件的结局是否指向下一个大事件的起因？"

---

### 分卷大高潮铁律

> **铁律：每个分卷必须有一个大高潮。** 大高潮是分卷的"存在理由"——读者读完这一卷，最应该记住的就是大高潮。

**大高潮与小高潮的层级关系**：

| 层级 | 名称 | 范围 | 频次 | 作用 |
|------|------|------|------|------|
| **分卷** | 大高潮 | 一卷之内（100-200章） | 每卷至少1个 | 分卷的情绪最高点——读者读完一卷后最深的记忆点 |
| **大事件** | 小高潮 | 一个大事件之内（20-100章） | 每个大事件至少1个 | 大事件的情绪引爆点——支撑读者持续追读的动力节点 |

> 大高潮通常位于该卷靠后位置（如倒数第二或第三个大事件）——在前面大事件的小高潮层层铺垫之后，大高潮将情绪推到全卷顶点，之后留有1-2个大事件或过渡事件来收尾和处理后果。大高潮所在的章节篇幅和情感强度应**明显高于**本卷内所有其他章节。

**大高潮设计自检**：
- "如果读者向朋友安利这一卷，脱口而出的第一个场景是什么？" —— 应该是大高潮
- "大高潮在本卷中的位置是否合理？（通常在大事件的后半段——不是开篇、不是全卷最后一章、之后留有收尾空间）"
- "大高潮之前的大事件是否在逐步铺垫情绪和冲突？（大高潮不能从天而降）"
- "大高潮之后是否有足够的收尾空间？（至少1-2个大事件或过渡事件来处理大高潮的后果和引出下一卷）"

---

### 篇幅分配原则

**核心原则：事件的价值决定篇幅，而非事件的数量决定篇幅。**

每个事件的篇幅权重由以下因素决定：
- **主线推进度**：该事件对主线推进多少？推进主线越多 → 篇幅越多
- **人物弧光贡献**：该事件对主角/核心配角的人物成长贡献多大？
- **高潮价值**：该事件是铺垫、过渡还是高潮？高潮事件的篇幅应显著多于铺垫事件
- **读者期待度**：读者最想看什么？最期待的部分应给最多篇幅

**实操规则**：
- 一个分卷通常有1-2个核心事件（占该卷40-50%篇幅），其余为辅助事件
- 辅助事件中，推进主线的优先于日常过渡
- 一个5事件的分卷，不是每个事件20%篇幅——而是核心事件各占30%，其余三个共占40%
- 事件再小也不能没有篇幅，但事件再大也不能无限膨胀——用"讲清楚、节奏舒服"来判断

### 大事件的组织结构

大事件是完整大纲层面的组织单位（20-100章），由多个小事件构成，描述一个完整的任务或阶段。大事件内部可以穿插战斗和日常章节，节奏由事件交替决定。

#### 大事件的构成

```
大事件（20-100章，约等于一个"事件"）
├─ 小事件A（战斗事件，3章）：过渡+初次交锋
├─ 小事件B（日常事件，2章）：战斗后的休整和角色互动
├─ 小事件C（战斗事件，4章）：深入推进+关键遭遇战
├─ 小事件D（日常事件，2章）：发现关键信息、角色关系深化
├─ 小事件E（小高潮战斗，5章）：决定性战斗——情绪引爆点
└─ 小事件F（过渡收尾，2章）：战果展示+引出下一大事件
```

#### 节奏编排

大事件内的节奏由战斗事件和日常事件的交替决定：

| 氛围 | 编排方式 | 适用场景 |
|------|---------|---------|
| **紧张氛围** | 连续战斗事件（2-3个），中间用短过渡（半章）衔接 | 危机、追击、时间紧迫的任务 |
| **张弛交替** | 战斗事件和日常事件交替排列——战斗后必有日常缓冲 | 多数大事件的标准节奏 |
| **轻松为主** | 日常事件为主，战斗事件为辅 | 探索、经营、角色关系深化阶段 |

> **铁律**：一个大事件必须至少有一个**小高潮**——一个在篇幅和情感强度上明显高于其他小事件的关键战斗或情绪爆发点。**小高潮战斗不得少于2章**——单章战斗无法承担小高潮的情绪重量和展开空间。没有小高潮的大事件 = 读者不知道"这一段为什么要写这么长"。
>
> **大高潮 vs 小高潮**：大高潮是分卷级别的最高情绪点，通常是一个特定大事件的小高潮（或该大事件小高潮的升级版）。一个大事件的小高潮如果被指定为分卷的大高潮，其篇幅、情感强度、剧情分量应在本卷所有小高潮中排名第一。

#### 大事件示例：迷雾森林探险（假设为某卷第二个大事件，非大高潮）

```
大事件：迷雾森林探险（约20章）
├─ 小事件1（日常+过渡，2章）：城镇收集情报、采购物资、接受委托
├─ 小事件2（战斗事件，3章）：进入森林 → 遭遇魔兽群，初次战斗
├─ 小事件3（日常事件，2章）：林中扎营、队友互动、发现前人留下的标记
├─ 小事件4（战斗事件，4章）：深入密林 → 遭遇守护者/强大的领地魔兽
├─ 小事件5（日常+过渡，2章）：受伤队友休整、从遗留物中拼凑出森林的秘密
├─ 小事件6（小高潮战斗，5章）：与森林核心区域的boss决战 → 揭示委托的真相
└─ 收尾过渡（2章）：战果展示、回收伏笔、引出下一阶段的线索
```

#### 与其他层级的关系

- 大事件对应完整大纲中的"事件"（层级二）
- 大事件内的每个小事件在细纲中展开为具体章节（层级三，见下方「小事件维度」）
- 大事件的篇幅范围（20-100章）不是硬性约束——用"讲清楚、节奏舒服"判断

### 输出格式

```
# 完整大纲：第X卷 {卷名}

## 卷概述
- 起止章节：第X章 - 第X章
- 核心目标：
- **本卷大高潮**：【必填】在哪个大事件中爆发？具体是什么场景？（这部分是本卷最重要的定义——读者读完这一卷，最应该记住的就是这里）
- 大事件数量：X个

## 大事件列表
| 大事件 | 章节范围 | 类型 | 篇幅占比 | 小高潮 | 备注 |
|--------|---------|------|---------|--------|------|
| 事件一：{事件名} | 第X-X章 | 铺垫事件 | XX% | 第X章（XX场景） | |
| 事件二：{事件名} | 第X-X章 | 核心事件 | XX% | 第X章（XX场景） | |
| 事件三：{事件名} | 第X-X章 | ⭐大高潮事件 | XX% | 第X章（XX场景）——**本卷大高潮** | 本卷情绪最高点 |
| ... | ... | ... | ... | ... | |

> **事件类型**：⭐大高潮事件（全卷情绪最高点）/ 核心事件（主线推进主要贡献者）/ 辅助事件（人物塑造/设定揭示/支线）/ 过渡事件（衔接+信息负载）

## 事件详情
### 事件一：{事件名} {类型}
- 起止章节范围：第X章 - 第X章
- 篇幅占比：约XX%（本卷内）
- 小事件构成：战斗事件X个 + 日常事件X个 + 小高潮1个
- 核心冲突：
- 涉及人物：{参考角色/文件夹}
- 主要看点：
- 本事件如何为后续事件铺垫：{如果是铺垫事件——它为大高潮事件贡献了什么信息/情绪/人物关系？}
```

> **过渡到细纲**：完整大纲完成后，每个大事件都需要独立创建细纲文件。但不需要一次性全部完成——写到哪个大事件，就为那个大事件创建细纲。大高潮事件的细纲应优先完成（其篇幅和情感设计需要最早敲定）。

---

## 层级三：细纲 — 章节级规划

**尺度**：单一大事件之内，落实到每一章。
**文件位置**：`大纲/细纲/{事件名}-细纲.md`（**每个事件一个独立文件**）

> **为什么要分开**：细纲内容详细，全部放一个文件难以维护。按事件拆分后，写作时只打开当前文件，清晰且专注。

---

### 章节类型定义与篇幅分配

细纲中的每一章必须标注其**章节类型**。类型决定了该章的写作重点、节奏和篇幅范围。一章可以是单一类型，也可以是类型组合（如"前半过渡，后半开启战斗"）。

#### 类型一：战斗类

**篇幅范围**：

| 战斗规模 | 篇幅 | 适用场景 |
|---------|------|---------|
| 小战斗 | 半章 ~ 一章 | 遭遇战、试探性交锋、单挑速决 |
| 常规战斗 | 一章 ~ 三章 | 有来有回的团队战、阶段boss战 |
| 大高潮战斗 | 三章 ~ 五章 | 事件最终决战、分卷高潮战 |

**写作重心**：节奏 + 交互感 + 后果。具体写作技法见「myworkflow:具体写作」skill 锚点A。跨章战斗时，每章结尾必须在战斗的关键回合切断（见下方「事件跨章原则」）。

#### 类型二：日常类

**篇幅范围**：半章 ~ 二章

日常章是**塑造人物的核心场所**——在非战斗压力下，通过日常互动展示角色的性格侧面、加深关系、暗埋伏笔。日常以有趣为主导：有趣的互动、有趣的发现、有趣的细节。

**篇幅判断**：一件日常小事通常半章到二章——取决于这件事对人物塑造的贡献。对人物关系有重大推进的日常可以给足篇幅，纯过渡性质的日常精简处理。

#### 类型三：过渡类

**篇幅范围**：半章 ~ 一章

过渡章负责推进剧情和埋伏笔——移动途中、战斗间隙、事件之间的衔接。过渡不是"可有可无的填充"，而是让剧情逻辑连贯的必要环节。

**过渡的嵌入方式**：
- 作为独立章存在（纯过渡章，半章到一章）
- 嵌入其他类型的章中（战斗章前半过渡引出敌人、日常章后半过渡引向冲突）
- 在多处分散嵌入——过渡不限于章的开头或结尾，可以在任何需要的节点插入

> **过渡的底线**：纯粹的"他们在路上走了两天"不是过渡——过渡必须负载信息增量（环境描写建立世界观、角色对话推进关系或埋伏笔、发现线索指向后续剧情）。

#### 类型组合

一章可以由多种类型组合。常见组合模式：

| 组合模式 | 结构 | 示例 |
|---------|------|------|
| 过渡+战斗 | 前半过渡（引出敌人/到达战场），后半开启战斗，在交火中切章 | 穿越密林发现敌营 → 战斗开始，第一轮交锋后切章 |
| 战斗+过渡 | 前半战斗收尾，后半过渡到下一事件 | 击败敌人 → 打扫战场、引出新线索 |
| 日常+过渡 | 前半日常互动，后半过渡引向下一冲突 | 队友聚餐闲聊 → 收到紧急传信，气氛转变 |
| 过渡+日常 | 前半赶路/移动，后半安顿下来日常互动 | 到达新城镇 → 逛街、角色互动 |

> **组合原则**：过渡部分和核心部分之间必须有因果关联——不是因为"该打了"所以前面加过渡，而是过渡中的信息自然引出核心事件。

#### 跨章篇幅分配

篇幅分配不必在一章内完成。一个常规战斗（目标3章）的分配示例：

- 第1章：过渡（到达战场、观察敌情）+ 战斗开始（第一轮交锋）——战斗占半章
- 第2章：纯战斗章——拉锯、策略、转折
- 第3章：战斗高潮+收尾过渡——战斗占大半章，章末过渡到下一事件

> **核心原则**：篇幅服务于内容，不以"凑满X章"为目标。战斗拖太长失去张力，日常写太多变流水账，过渡太啰嗦拖慢节奏。唯一判断标准："讲清楚了吗？节奏舒服吗？"

### 小事件维度：过渡+核心结构

小事件是细纲中位于"章节"之上的组织单位——由若干章组成一个完整的微型故事单元（2-5章）。每个小事件有一个明确的核心，结构为"过渡在前，核心在后"。

#### 小事件结构

```
小事件（2-5章）
├─ 过渡部分（1-2章）：引出核心事件
│   - 什么触发了核心事件？（起因）
│   - 人物如何被卷入？（动机）
│   - 过渡中负载了什么信息？（世界观/线索/伏笔）
└─ 核心部分（1-3章）：小事件的主体
    - 战斗事件：战斗过程
    - 日常事件：日常互动的核心场景
```

> **极少情况**：核心后面可以埋伏笔，但只能用几句话（如战斗结束后发现的一个细节、一句引人深思的对话）——不能变成另一个过渡段落。

#### 小事件类型

**① 战斗事件**：以一次战斗为核心

- 结构：过渡（战斗起因/到达战场）→ 核心（战斗过程）
- 篇幅：2-5章
- 示例：收到求救信号（过渡1章）→ 与魔兽战斗（核心2章）= 共3章
- 章内安排：过渡章可能半章过渡+半章战斗开始；核心章可以是纯战斗或战斗+收尾

**② 日常事件**：以一个日常互动/场景为核心

- 结构：过渡（日常起因/场景设置）→ 核心（日常事件本身）
- 篇幅：2-5章
- 示例：采购路上发现奇怪商人（过渡0.5章）→ 回营地后队友一起研究买到的奇怪物品、展现各自性格（核心1.5章）= 共2章
- 章内安排：过渡和核心可以在同一章内完成（日常+过渡组合章）

#### 过渡的编排规则

- **过渡不能重复**：相邻小事件的过渡方式要有变化。如果上一个战斗事件用"赶路途中遭遇敌人"过渡，下一个战斗事件换"在城镇休整时突然被伏击"或"主动出击搜寻敌人老巢"（详见下方「重复性审查」）
- **小事件的切分**：过渡在前（什么引出了核心事件），核心在后（发生战斗或日常事件）。读者读完过渡自然期待核心——如果过渡后不给核心，读者会觉得被耍

### 重复性审查

重复是长篇连载的头号敌人。同样的战斗策略、同样的日常套路、同样的人物塑造手法——第二次出现时效果减半，第三次出现时读者弃书。

#### 短距离审查：相邻小事件的区别

细纲规划时，每新增一个小事件，反向检查前一个小事件：

| 检查维度 | 战斗事件 | 日常事件 |
|---------|---------|---------|
| 触发方式 | 主动出击 vs 被动遇敌 vs 救援 vs 伏击 | 计划中的活动 vs 意外相遇 vs 外部事件引发 |
| 敌人/对象 | 敌人类型/数量/策略是否不同？ | 互动的对象/主题/情绪基调是否不同？ |
| 环境 | 战场地形/天气/时间是否不同？ | 场景/时间/氛围是否不同？ |
| 结果 | 胜负平/撤退？是否与上次相同？ | 关系推进方向是否不同？ |

> **最低要求**：相邻小事件至少在以上两个维度上有显著区别。四个维度全部相似 → 合并或重新设计。

#### 长线审查：重复性记录文件

在 `进度/重复性记录.md` 维护一个持续更新的文件，记录已经使用过的核心策略和人物塑造事件。**每完成一个小事件后立即更新**。

**文件格式**：

```
# 重复性记录

## 战斗策略
| 编号 | 策略描述 | 使用章节 | 所属事件 |
|------|---------|---------|---------|
| B001 | 主角为守护朋友而爆发，越级战胜对手 | 第45章 | 迷雾森林boss战 |

## 人物塑造事件
| 编号 | 塑造内容 | 使用章节 | 涉及人物 |
|------|---------|---------|---------|
| C001 | 雨天朋友聊天打趣，展现日常默契 | 第12章 | 主角+搭档 |
| C002 | 围篝火聚会，每人分享一段过去 | 第28章 | 全队 |

## 日常场景
| 编号 | 场景 | 使用章节 | 情绪基调 |
|------|------|---------|---------|
| D001 | 采购/逛街中发生意外插曲 | 第8章 | 轻松搞笑 |
```

**使用方式**：
- 细纲规划新小事件时，查阅此文件，避免使用已记录的策略/塑造事件/场景
- 写前审查时检查：本章的内容是否与记录中的已有内容重复？
- 此文件随写作进度持续增长——是全书"已有素材库"的索引

#### 允许的重复（需额外审批）

以下情况允许有控制的重复，但必须向用户明确说明理由并获得批准：

| 允许重复的场景 | 条件 | 示例 |
|-------------|------|------|
| **前后呼应（callback）** | 必须是不同阶段的同一场景/行为，因人物成长而产生不同意义 | 开篇大家在篝火旁初次聚会（陌生拘谨）→ 成长后回到原地再次篝火聚会（生死之交）——场景相同，情感重量完全不同 |
| **人物标志性行为** | 行为本身是人设的四维行为塑造中定义的特征，跨章重复是强化人物辨识度，不是策略重复 | 慵懒型角色每次思考时都半睁眼叹气——这是人物标签的外显 |

> **审批流程**：使用上述允许重复的场景前，向用户说明：之前在哪里使用过、这次如何不同、为什么值得重复。**未经用户明确批准，不得使用。**

### 启发式提问

- "这个大事件跨多少章？"
- "每章的核心内容是什么？（一句话概括）"
- "每章内容是否足够撑起一整章？是否需要补充场景或内容？"
- "哪些事件需要在章间断开以制造钩子？切点在哪里？"
- "每章的结尾钩子是什么？"
- "高潮在哪一章爆发？前面的章节如何铺垫？"

### 内容充实度检查：每章能否撑起一整章？

**核心原则：细纲中每一章的内容必须足以撑起一整章的文字量。如果撑不起，需要补充内容或合并章节。**

在规划每章内容时，必须自问：
- "这一章有足够的场景/对话/动作/心理描写来撑起一整章吗？"
- "这一章有几个独立场景？如果只有一个简短场景，撑不起一整章。"

**充实度不足的解决方案（按优先级排序）**：
1. **补充场景**：增加一个并行场景（另一组人物的行动、另一条线的推进）或过渡场景（移动中的对话、环境描写+心理活动）
2. **合并章节**：如果两个相邻章节各自内容都不够充实，且时间线连续，合并为一章——优先于深挖和插入，因为强行撑满两章不如扎实写好一章
3. **深挖现有内容**：在已有场景中深挖——加对话交锋、加内心独白、加环境细节、加动作描写
4. **插入微型事件**：在主线之间插入小型冲突或人物互动（信息交换、观点碰撞、能力展示），服务于人物塑造或伏笔埋设

> **充实≠注水**：补充的内容必须服务于主线推进、人物塑造、设定揭示或伏笔埋设——不能为了凑字数而写无关内容。

### 章节数调整原则

**核心原则：粗纲和完整大纲是方向指南，不是精确模具。细纲中的章节数以实际剧情需要为准。**

- 完整大纲中标注的章节范围是**估算值**。写细纲时允许且应当自主调整：
  - 事件复杂、需要更多铺垫或过渡 → 比大纲多1-3章，加
  - 事件可以紧凑处理、节奏更快 → 比大纲少1-2章，减
  - 发现大纲遗漏了必要的过渡/铺垫章 → 加
  - 发现两章内容可以合并且不影响节奏 → 并

- **判断依据**：不是"大纲说10章就必须10章"，而是"这个事件讲清楚、节奏舒服需要几章？"
- **同步更新**：细纲调整章数后，回看完整大纲中该事件的章节范围是否需要更新。如果调整影响了后续事件的起止位置，必须同步更新完整大纲。

### 事件跨章原则：事件不必在章末结束

**核心原则：抛弃"章节内必须是完整故事"的想法。一个事件可以（且应该）卡在两章之间。**

**为什么跨章切分事件？**
- **天然钩子**：事件进行到一半戛然而止 → 读者必须翻下一章。比任何刻意设计的钩子都自然。
- **字数灵活**：不再被"一章装下一个完整事件"束缚。长事件切2-3章，短事件一章可以塞两个。
- **节奏控制**：高潮场景切章制造悬念；日常场景完整收束给读者喘息——切与不切都是节奏工具。

**实操规则**：
- 细纲中标注：本章结尾时事件进行到什么程度？→ "事件A完成70%，主角刚发现关键线索"
- 下一章开头：无缝接续，不重复上文（读者刚读完一章，不需要回顾）
- 切点选择：信息即将揭晓时、冲突即将爆发时、决定即将做出时——在"答案揭晓前一秒"切
- 一章之内也可以同时推进两个事件线（A事件前半 + B事件前半 + 钩子），但单章事件线不超过2条，否则读者注意力分散

**切点的好位置**：
- 对话中：一个角色问出关键问题 → 切章
- 行动中：战斗进行到关键回合 → 切章
- 揭示中：主角发现线索但还没理解其含义 → 切章
- 决定前：角色面临选择、举起手准备行动 → 切章

## 层级四：伏笔管理

**尺度**：全书范围，跨层级跟踪。
**文件位置**：`进度/伏笔记录.md`

> **为什么伏笔文件在进度/而非大纲/**：伏笔是大纲层面的设计，但伏笔的"状态"（已埋/待回收/已回收）会随写作进度不断变化。放在进度文件夹下便于每次写作后更新状态。

### 伏笔规划（写之前）
- "在目前的事件中，有哪些信息可以留到后面揭示？"
- "打算埋多久？短（几章内）/ 中（一卷内）/ 长（跨多卷）？"
- "回收时希望达到什么效果？"

### 伏笔检查（写之后/定期）
- "有哪些长线伏笔的回收计划需要调整？"
- "有没有写了但忘记回收的伏笔？"
- "有没有无意中制造了新伏笔但不自知？"

### 输出格式

| 伏笔ID | 伏笔内容 | 类型 | 埋设章节 | 计划回收章节 | 实际回收章节 | 状态 |
|--------|---------|------|----------|-------------|-------------|------|
| F001 | | 短/中/长 | 第X章 | 第X章 | | 待回收 |

### 层级选择流程

```
你需要什么？
├─ "整本书从哪到哪？" → 粗纲
├─ "这一卷分几个事件？" → 完整大纲
├─ "这事件每章写什么？" → 细纲（⚠️ 写前审查的必需要素，不可缺少）
├─ "有没有忘了填的坑？" → 伏笔管理
└─ 不确定 → 先回答粗纲中的"结局方向"和"阶段规划"，方向不清时下层设计无锚点

标准创作流程（本skill内）：
  粗纲（全书方向+分卷规划） → 完整大纲（分卷大事件设计+大高潮锚定） → 细纲（章节类型+小事件维度+重复性审查） → 伏笔
  写前审查前必须有当前大事件的细纲。缺少细纲就进入写前审查 = 没地图就上路。
```

## 常见错误

| 错误 | 为什么错 | 正确做法 |
|------|---------|---------|
| 细纲写成"主角打了一架然后赢了" | 太模糊，写前不知道具体写什么 | 细到本章剧情走向、必须提到的内容、结尾钩子——三者缺一不可 |
| 粗纲中结局方向永远"待定" | 没有锚点的大纲是漂流——写到哪里算哪里 | 先写一个设想（可以调整），不要空着 |
| 伏笔只管埋不管查 | 遗忘的伏笔=没有回收的读者期待=最终弃书 | 每完成一个分卷检查伏笔记录 |
| 事件之间没有因果链 | A事件结束→"然后"B事件发生，不是"因为"A所以B | 粗纲中标注：A事件的结局如何指向B事件的起因 |
| 细纲一次性写到全书结尾 | 后期剧情会变化，提前写的细纲全浪费 | 只拆解当前要写的事件，其余粗纲足矣 |
| 大纲中提到的等级/技能在战力体系中不存在 | 写时发现"这个能力设定里没有"→卡住或硬编→矛盾 | 粗纲标注：主角升至XX级→查设定/战力体系.md确认该等级存在 |
| 完整大纲每个事件字数均分 | 核心事件和过渡事件花同样篇幅 → 读者觉得高潮不够、日常太拖 | 按"篇幅分配原则"为事件分级：核心事件占大篇幅，过渡事件精简 |
| 细纲的章数与完整大纲不符就强行凑 | 大纲是估算，不是模具 | 按剧情实际需要增减章数，同步更新完整大纲 |
| 细纲每章都标注"名场面" | 名场面多了就是没有名场面——十章一个名场面读者反胃 | 全卷3-5个名场面足矣。大多数章的看点是扎实的剧情推进，不是每章都要炸裂 |
| 细纲每章内容撑不起一整章 | 规划时觉得"这个事件可以写一章"但实际只有一两个场景 | 每章规划必须做充实度检查：有几个场景？够撑起一整章吗？ |
| 每章都是完整事件，事件从不在章中断开 | 放弃天然钩子，每章结尾需额外设计钩子 | 主动在事件关键位置切章——事件卡在章间=天然钩子，比任何后补钩子都有效 |
| 细纲不标注章节类型 | 不标注类型 → 不知道每章的写作重点和篇幅范围 → 战斗写成流水账、日常写成灌水 | 每章必标类型（战斗/日常/过渡/组合），按类型篇幅范围控制长度 |
| 大事件没有小高潮 | 读者读完一个大事件后"所以呢？"——不知道这一段为什么存在 | 每个大事件至少一个小高潮——篇幅和情感强度明显高于其他小事件的关键战斗，小高潮战斗不得少于2章 |
| 小高潮战斗只有1章 | 单章战斗无法承担小高潮的情绪重量——读者还没来得及投入就结束了 | 小高潮战斗至少跨2章，第1章铺垫+交火、第2章决战+收尾（或更多章展开） |
| 分卷没有大高潮 | 读者读完一卷后"这一卷到底讲了什么"——没有记忆点 | 每卷必须有一个大高潮（通常为某个大事件的小高潮的升级版），是本卷情绪最高点 |
| 完整大纲不显式列出大事件 | 只有事件编号没有事件列表——无法快速概览分卷结构 | 输出格式必须包含"大事件列表"表格：每行一个大事件，含章节范围/类型/篇幅占比/小高潮 |
| 相邻小事件重复 | 连续两个战斗事件都用"赶路遇敌"触发、都用"地形利用"策略 → 读者觉得"又是这一套" | 短距离审查：相邻小事件至少在两个维度上有显著区别（触发方式/敌人/环境/结果） |
| 长期使用相同策略不记录 | 第10章用过的"守护朋友爆发"到了第50章又用——读者发现套路，作者不自知 | 维护 进度/重复性记录.md，每完成一个小事件后记录使用的核心策略和塑造事件 |
| 过渡章没有信息增量 | 纯粹的"在路上的第三天"——过渡沦为填充物 | 过渡必须负载信息：世界观描写、角色对话推进关系或埋伏笔、发现线索 |

## 危险信号 — 停下重新检查

- 用户在粗纲中说"写到哪算哪" —— 对于百万字级长篇，没有方向锚定容易中期迷失
- 粗纲中的阶段规划每卷用同一句话概括 —— "主角升级→打怪→再升级"无差异化，说明对剧情缺乏思考
- 细纲仅剩3章就要用完了还没补新的 —— 写作会卡住，应该提前5-10章规划后续细纲
- 伏笔记录的"待回收"列有一半超过计划回收章节 —— 伏笔堆积如债，拖得越久越还不上
- 大纲中事件列表的首尾没有衔接关系 —— 事件链断裂处往往是"机械降神"的入口
- 细纲每章都写"完整收束"没有跨章切断 —— 没有钩子，读者读完一章后没有动力翻下一章
- 细纲多章内容重复、每章只有一次场景转换 —— 内容撑不起章数，应当合并章节或补充内容
- 大事件规划中没有小高潮 —— 读者读完这一大段后无法回答"为什么这一段要写这么长"
- 完整大纲中"本卷大高潮"字段为空白或"待定" —— 分卷没有锚点。大高潮是分卷的"存在理由"，不能留白
- 完整大纲的大事件列表中没有标注 ⭐大高潮事件 —— 所有事件看起来同等重要 = 没有事件真正重要
- 连续两个小事件在触发方式/敌人/环境/结果四个维度上全部相似 —— 这是重复，读者会察觉。立即检查，至少改两个维度
- 重复性记录文件超过10条但写前审查从不查阅 —— 文件沦为摆设。将"查阅重复性记录"嵌入写前审查流程
- 过渡章连续三章内容均为"赶路/移动/等待"且无信息增量 —— 过渡在凑章数，应当压缩或并入其他章
