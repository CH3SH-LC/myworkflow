# Skill：整体架构 — 从零开始创建小说项目

## 触发场景
- 开始一个全新的小说创作项目
- 需要重新梳理已有项目的基础结构

> 本 skill 仅在项目启动或彻底重建时执行一次。其余所有 skill（设定/人物/大纲/审查/写作）均可在写作过程中随时返回补充或调整。

## 必需要素
- 无（这是起点）

## 推荐要素
- 无

## 前置强制步骤

> **核心原则：指南文件是本书的"宪法"。** 本skill的所有输出——从文件夹结构到 CLAUDE.md 到风格定位——都必须以指南文件为最高准则。指南中的每一条规则、每一个禁忌、每一项风格要求，都在本skill的执行中自动生效。

1. **检查是否已有指南文件**：如果项目已存在（非首次启动），读取 `指南/` 文件夹下所有文件：
   - `指南/风格定位.md` — 本书的整体风格和基调
   - `指南/` 下的其他专属规则文件
   → 如果已存在指南文件，本skill的所有提问和输出都必须符合已有指南

2. **检查是否已有 CLAUDE.md**：如果项目已存在，读取 CLAUDE.md 了解当前创作状态
   → 本skill的操作必须与当前状态衔接

## 目标
帮助用户从零开始创建一个标准化的网络小说创作项目，建立文件夹结构，并通过启发式提问引导用户明确小说的核心定位。

## 执行流程

### 第一步：创建项目文件夹结构

在当前目录下创建以下文件夹结构：

```
小说名/
├── CLAUDE.md          # 项目说明文件，记录协作规则、项目概览、工作流映射
├── 大纲/               # 存放所有大纲文件
│   ├── 粗纲.md        # 全书骨架（一个文件，全书层面）
│   ├── {卷名}-完整大纲.md  # 每卷一个文件，拆分事件和冲突
│   └── 细纲/          # 细纲按事件拆分为独立文件（每个大事件一个文件）
├── 角色/               # 存放人物设定文件（主要人物、临时人物、龙套）
├── 设定/               # 存放世界观、战力体系、专有名词等设定
│   └── 索引.md        # 设定总索引，汇总所有设定便于查找
├── 正文/               # 存放正式创作的章节内容
├── 进度/               # 存放进度跟踪、时间线、伏笔记录
└── 指南/               # 存放本书专属的写作参考（见下方说明）
```

#### 关于「指南」文件夹

`指南/` 存放的是**这本书专属**的写作参考，随书而异。每个 skill 在执行时会读取指南文件，确保本书的特殊要求贯穿始终。

- **风格定位**：这本书的整体风格要求（如"轻松幽默为主，战斗时切换严肃"）
- **专属写作规则**：如"主角需要每章至少一个小剧场"、"配角吐槽不超过每章2次"
- **人物战力模板**：根据本书的战力体系，明确某个人物的具体等级/属性/技能数值
- **特殊注意事项**：这本书特有的禁忌或偏好（如"不要写主角的父母"、"不要出现XX类型的情节"）
- **参考范例**：如果这本书有对标作品或风格参考，放在这里

> 「指南」中的内容仅适用于当前这本书。通用写作方法论（如何写大纲、设计人物、审查等）已内嵌在各个 skill 的执行流程中。

创建后告知用户结构已就绪，并开始提问。

### 第二步：启发式提问 —— 明确小说核心定位

分两轮进行：第一轮通过结构化问卷快速确定基本框架，第二轮用纯文本追问深挖细节。

---

#### 第一轮：结构化问卷（使用 AskUserQuestion）

> 使用 `AskUserQuestion` 工具一次性发送以下 4 个问题。用户提交后，根据选中的选项进行针对性追问。

**Q1** | header:"小说类型" | multiSelect

- "玄幻/仙侠": 东方修炼体系、修真、飞升、丹药、法宝、宗门、仙魔
- "都市/科幻": 现代异能、系统流、未来科技、星际文明、机甲
- "网游/末世": 虚拟现实、游戏世界、数据化、丧尸、废土生存
- "历史/奇幻": 穿越古代、权谋、争霸、西方魔法、剑与魔法、多种族

**Q2** | header:"叙事框架"

- "穿越": 现代人穿越到异世界
- "重生": 带着记忆回到过去，重活一世
- "系统流": 主角携带游戏化系统外挂
- "原生世界": 主角就是这个世界的原住民

**Q3** | header:"开局状态"

- "穿越/觉醒": 刚穿越到新世界，或能力刚刚觉醒
- "危机开局": 第一章就面临生死危机
- "重生开局": 带着前世记忆回到人生关键节点
- "日常打破": 平静的日常被某个突发事件打破

**Q4** | header:"主线类型"

- "废材逆袭": 从底层一步步登顶，成长感为核心
- "复仇": 核心驱动力是为某人/某事复仇
- "拯救世界": 对抗毁灭性的外部威胁
- "争霸天下": 建立势力、统一天下、开创时代

> 用户提交后，根据回答追问：有没有特别想写的创新点或融合方向？

---

#### 第二轮：纯文本追问

逐一提问以下问题，根据用户回答深入追问：

##### 1. 小说标题
- "目前有没有想好的书名？"
- "如果没有，我们可以先确定核心概念，之后再来想标题。"

##### 2. 核心卖点
- "如果让你用一句话向读者推荐这本书，你会说什么？"
- "这本书最吸引人的地方是什么？和其他同类小说最大的区别在哪里？"
- "你希望读者看完这本书后记住什么？"
- 追问：这个卖点能支撑多长的篇幅？是否足够差异化？

##### 3. 开篇引子
- "故事从什么地方开始？"
- "第一章的场景、时间、大致氛围是怎样的？"
- "开篇有没有一个能立刻抓住读者的冲突或悬念？"

##### 4. 故事主线展开
- "主线大致可以分为几个阶段？"
- "主角的终极目标是什么？"
- "主线之外有没有重要的支线？"

##### 5. 结局方向
- "你心中有没有设想过故事最终会怎么收尾？"
- "主角的结局状态是什么？（登顶/归隐/牺牲/开放式……）"
- "如果没有明确想法也没关系——可以先标注为『待定』，但建议在写完第一分卷后重新思考这个问题。"
- "故事有结局方向，可以避免中期迷失和后期乏力。"

### 第三步：生成基本指南框架

根据用户对小说类型、风格、基调的回答，在 `指南/` 下生成**基本框架文件**。这些是初始骨架——详细的风格设计、禁忌审查、特殊约束由「myworkflow:本书个性化设计」skill 完成。

**指南/风格定位.md**：
```markdown
# 本书风格定位

## 整体基调
{根据用户回答填写：幽默但不轻浮 / 严肃史诗 / 轻松日常 / 黑暗向……}

## 本书特有规则
{根据用户回答填写，如：每章至少一个小剧场、禁止出现XX类型角色}

## 本书禁忌
{根据用户回答填写，如：不让主角降智、不写沉重告别仪式}

## 写作风格要求
{根据用户回答填写具体的文风偏好，如：短句为主、对话占比高、环境描写精简}

## 人物风格偏好
{根据用户回答填写，如：主角必须讨喜、反派要有魅力、配角要有独立人格}
```



> **指南文件的宪法地位**：
> - 指南文件一旦生成，所有后续 skill 在执行前**必须**先读取指南文件
> - 指南中的每一条规则，在后续 skill 中自动生效——不需要用户重复提醒
> - 指南文件随时可以补充修改。后续写作中如果发现新的偏好或禁忌，直接追加
> - 如果指南中的规则与通用 skill 规则冲突 → **指南优先**（这是本书专属要求）
>
> **关于结构规则、内容规则、禁止事项**：这些将在「myworkflow:本书个性化设计」中细化——结构/内容规则融入「风格定位」的各章节类型表中，禁止事项独立为「书籍禁忌」文件。本步只生成基本骨架。

> **下一步**：基本框架就绪后，调用「**myworkflow:本书个性化设计**」进行深度定制——启发式提问填充全部 5 个指南文件、交叉审计、生成记忆摘要。指南文件的完整生命周期由本书个性化设计管理。

### 第四步：生成初始CLAUDE.md

根据用户回答，生成项目根目录的 `CLAUDE.md`。**CLAUDE.md 是本书的"仪表盘"——每次操作后必须更新，每次操作前必须读取。**

```markdown
# {小说名} — 创作项目

## 基本信息
- **类型**：{小说类型}
- **标题**：{小说标题}
- **核心卖点**：{一句话卖点}
- **开篇引子**：{开篇概述}
- **故事主线**：{主线概述}
- **结局方向**：{结局设想 / 待定}

## 本书宪法（指南文件）
> 以下指南文件是本书的最高准则。所有 skill 执行前必须读取，执行中必须遵守，执行后必须对照。
- [指南/风格定位.md](./指南/风格定位.md) — 整体基调、本书禁忌、写作风格要求（初始骨架）
- 其他指南文件（由「myworkflow:本书个性化设计」创建和管理）→ 同样具有宪法地位

## 文件夹结构
- 大纲/ — 粗纲 + 完整大纲（按分卷） + 细纲（按事件拆分）
- 角色/ — 人物设定
- 设定/ — 世界观、战力、专有名词等（索引见 设定/索引.md）
- 正文/ — 已完成章节
- 进度/ — 进度跟踪、时间线、伏笔记录、重复性记录
- 指南/ — 本书专属写作参考（宪法地位——所有 skill 的最高准则）

## 工作流（需求驱动，非固定顺序）

### 核心原则
1. **指南优先**：所有 skill 执行前必须先读取 `指南/` 文件夹下的所有文件。指南中的规则自动生效，不需要用户重复提醒
2. 不强制顺序——人物、设定、大纲可按任意顺序进行，但**推荐**：设定 → 人物 → 大纲
3. 写作过程中随时可返回补充——新增人物、补充设定、调整细纲
4. 每个 skill 独立可用——只做当前需要的部分
5. 写前审查是每次写作的**必过关卡**
6. 大纲有层级依赖：粗纲 → 完整大纲 → 细纲。细纲是写前审查的必需要素——没有细纲就写，等于没有地图就上路
7. **每次操作后更新状态**：任何改变项目状态的 skill 完成后，必须更新本文件的"当前创作状态"和对应的进度文件

### Skill 速查表

| 你想做什么 | 调用 |
|-----------|------|
| 设计世界观/战力/专有名词 | 明确设定 |
| 创建或补充人物（主角/配角/龙套） | 人物设计 |
| 规划全书走向 | 大纲设计（粗纲层） |
| 规划分卷事件 | 大纲设计（完整大纲层） |
| 写某事件前拆解章节 | 大纲设计（细纲层） |
| 管理伏笔埋设与回收 | 大纲设计（伏笔层） |
| 深度定制本书风格/禁忌/约束 | 本书个性化设计 |
| 每次写作前检查准备情况 | 写前审查 |
| 开始写正文 | 具体写作 |
| 写完一章后检查质量 | 章节审查 |
| 定期检查全局一致性 | 全书一致性审查 |

### 推荐初始流程
首次启动：整体架构 → 明确设定 → 人物设计 → 大纲设计（粗纲 → 完整大纲 → 当前卷细纲）
之后每次写作循环：大纲设计（细纲）→ 写前审查 → 具体写作 → 章节审查
定期维护：全书一致性审查（每10-15章或每完成一个分卷）

### 中断恢复
如果工作流中断，查看下方的"当前创作状态"字段确定：
- 上次执行了什么
- 下一章是什么
- 然后对照 Skill 速查表决定接下来调用什么

## 当前创作状态

- **当前写作位置**：{第X章 / 事件名}
- **下一章内容**：{简述}
- **当前卷/分卷**：{卷名}
- **当前大事件**：{事件名}
```

## 常见错误

| 错误 | 为什么错 | 正确做法 |
|------|---------|---------|
| 跳过结局方向提问 | 没有方向会在中期迷失，后期草草收尾 | 即使答"待定"也要提问并标注——写完第一分卷后回来重答 |
| 指南/中写入通用写作规范 | 通用写法已内嵌在各 skill 流程中，混在指南/中会模糊本书专属规则的边界 | 指南/只放**本书专属**内容（风格定位、禁忌、数值模板） |
| CLAUDE.md 生成后不更新 | CLAUDE.md是"当前创作状态"的仪表盘，过期等于废纸 | 每完成一章更新创作位置和审查状态 |
| 进度文件空模板一直不填 | 空模板是空洞承诺——写作时没有追踪工具 | 写完第一章立即填入时间线和伏笔表格 |
| 启发式提问跳着问 | 漏掉的问题往往是后面设计师卡壳的根因 | 第一轮4个结构化问题+第二轮5个追问逐一确认 |
| 文件夹立即创建所有文件而不问用户 | 用户可能已有部分设定想用已有内容 | 创建结构后先提问，文件内容来自用户回答 |

## 危险信号 — 停下重新检查

- 用户说"随便"或"你定就行" —— 核心定位不能由AI拍板，必须追问出真实意图
- 启发式提问答到第三组就觉得"差不多了"  —— 每组问题覆盖不同维度的盲区，不全问必有遗漏
- CLAUDE.md 生成后发现"当前创作状态"全是0和空 —— 说明还没真正开工，需要确认是否工具就绪
- 用户说"结局以后再想吧" —— 追问一次"先标注待定可以吗？"，如果用户坚持则尊重，但必须在CLAUDE.md中标记⚠️待定
- 进度文件创建后超过一周仍为空 —— 写作没有推进，或文件结构有问题导致用户找不到
