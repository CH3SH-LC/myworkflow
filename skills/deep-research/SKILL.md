# 深度调研

## 触发

- **必须触发**：调研/研究/全面了解/写报告、技术选型与方案对比（"A vs B"）、需多来源验证的事实问题、查"XX 最新状况"。
- **不触发**：简单事实查询（直接搜索回答）、纯代码问题（走代码通道）、用户已有明确答案只需确认。

## 前置强制步骤

1. **禁止用自身知识替代搜索**——训练数据可能过时/有偏见，即使知道答案也必须实际搜索。
2. **锁定范围**：请求模糊 → AskUserQuestion 缩小（≤3 轮）；仍模糊 → 报告中标注"范围基于以下假设：…"。
3. **声明不确定**：查不到的信息标注"信息缺口"，不编造。
4. **🔴 硬门禁——报告必须落盘为本地 .md 文件**，禁止仅对话输出；对话只给 ≤5 行摘要 + 文件路径，无例外。

## 主线

**明确范围 → 多源并行搜索 → 交叉验证 → 综合报告**；发现矛盾或可信度不足 → 补充搜索（聚焦）后回写。

## 阶段 1：明确调研范围

1. **解析用户意图**：提取 主题 / 深度（概览→快速，学术级→完整流程）/ 时效性 / 输出形式（强制 .md）/ 约束（语言、地域、排除项）。
2. **锁定问题**（模糊时逐项缩小）：① 缩小主题 ② 确认深度 ③ 确认输出细节（默认 `docs/information/YYYY-MM-DD-research-<slug>.md`）。超 3 轮仍模糊 → 列假设。
3. **生成调研提纲**（核心问题一句话 / 子问题 / 搜索关键词中英文 / 排除项），获用户确认或"直接开始"。
4. **出口**：核心问题一句话说清、提纲已生成、用户已确认。

## 阶段 2：多源搜索（并行）

1. **设计搜索维度**（从以下选 ≥3 个；多源并行 → 派发子智能体）：
   - 官方文档 `<topic> official documentation`；社区讨论 `<topic> reddit/hackernews`；对比评测 `<A> vs <B> comparison`；学术/技术博客 `<topic> deep dive`；中文社区 `<主题> 实践 经验`；GitHub/开源 `<topic> github stars`；定价/成本 `<service> pricing`；负面/批评 `<topic> problems/issues`。
2. **每维度一个搜索子任务**：WebSearch ≥3 次不同关键词组合 → 选 3-5 个最相关来源 → WebFetch 全文 → 提取与提纲相关的关键信息 → 输出 `来源 | URL | 关键发现 | 可信度` 表 + 详细摘录。
3. **可信度**：🟢 官方/权威/同行评议/数据可复现；🟡 知名博客/社区高赞/公司技术博客；🔴 个人博客/匿名/未注日期/明显偏见。
4. **出口**：≥3 维度并行、每维度 ≥2 个有效来源、总来源 ≥8、每个来源已标可信度。

## 阶段 3：交叉验证

1. **提取核心声明**为清单（声明 → 来源 A/B/C → 验证状态）。
2. **分类处理**：
   - ✅ ≥2 独立来源确认 → 纳入报告，标注来源。
   - ⚠️ 单一来源 → 纳入但标"单一来源，未交叉验证"。
   - ❌ 来源矛盾 → **触发补充搜索**，聚焦矛盾点找第 3-4 个来源裁决。
   - 🔴 无来源 → 标"信息缺口"，建议用户其他渠道。
3. **处理矛盾不选边站**：补充搜索聚焦矛盾；报告呈现各方观点及依据；给出基于方法论的判断但标"仅供参考"。
4. **出口**：核心声明全列入、每声明 ≥2 来源（或已标注单一/矛盾/缺口）、矛盾已补充搜索、缺口已标注。

## 阶段 4：综合报告

按 8 章节结构落盘：

```markdown
# 调研报告：<主题>
> 调研日期 / 调研范围 / 来源数量 / 可信度

## 1. 执行摘要
[3-5 句总结]；核心结论：[一句话]（可信度）

## 2. 调研方法
搜索维度 / 来源总数 / 来源类型分布 / 验证方法；基于的假设

## 3. 调研发现
3.1 <子问题1> [详细分析，引用来源]

## 4. 方案对比（如适用）
维度 | 方案 A | 方案 B | 方案 C；推荐

## 5. 对立观点与争议
## 6. 信息缺口
## 7. 来源清单
| # | 标题 | URL | 类型 | 可信度 | 引用点 |
## 8. 建议与下一步
```

### 落盘（🔴 强制，不可跳过）

报告**必须**写入本地 `.md`，严禁仅对话输出。路径优先级：`docs/information/YYYY-MM-DD-research-<slug>.md`（有 `docs/`）→ 项目根 `research-<slug>.md` → 当前目录。`<slug>` = 主题英文 kebab-case（如 `python-web-frameworks`）。

写入后验证：Read/Glob 确认文件存在且非空、8 章节完整、来源清单完整（URL + 可信度 + 引用点）。

对话中仅允许 ≤5 行摘要 + 文件路径。

## 完成标志

- [ ] 提纲已生成并经用户确认（或"直接开始"）
- [ ] ≥3 搜索维度并行执行，总来源 ≥8 个独立来源
- [ ] 核心声明已交叉验证（≥2 来源或已标注单一/矛盾/缺口）；矛盾已补充搜索
- [ ] 报告 8 章节完整，声明有来源标注，信息缺口已标注
- [ ] 🔴 已落盘 .md（已 Read/Glob 验证存在非空）
- [ ] 对话仅 ≤5 行摘要 + 文件路径（未贴全文）

## 反绕过红线

- 只搜一个维度/一个关键词就"查完" → 覆盖面不足。
- 所有来源说法一致 → 可能同源互引，检查是否独立来源。
- 用自身知识代替搜索 / 把矛盾简化成"大家普遍认为" → 违规。
- 🔴 只在对话贴全文不写文件 → 硬门禁违规，先写文件再给摘要。
- 写完后未 Read/Glob 确认文件存在 → 可能写入失败。
